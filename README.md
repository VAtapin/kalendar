# Календарная мастерская

Локальное приложение для подготовки многостраничных православных настенных
календарей к печати. Основной результат работы программы - редактируемый проект и
готовый многостраничный PDF типографского качества.

Это не сайт с календарём и не генератор стандартной HTML-таблицы. Приложение
проектируется как небольшой издательский layout-редактор, в котором православная
календарная сетка является специальным интеллектуальным объектом страницы.

## Текущее состояние

Уже реализована рабочая сквозная версия редактора:

- Vue 3 + TypeScript + Vite;
- независимая от Vue и DOM модель печатного документа;
- геометрия документа исключительно в миллиметрах;
- пустая страница A3 Portrait 297 x 420 мм;
- bleed 3 мм;
- настраиваемая safe area, включая увеличенный верхний отступ под пружину;
- экранные линейки с миллиметровыми делениями;
- форматы A3, A4, A5 и A6 в книжной и альбомной ориентации;
- постраничное дерево слоёв: один объект на слой, папки с неограниченной вложенностью,
  порядок, переименование, видимость и блокировка;
- независимая функция построения сцены страницы;
- издательский интерфейс: меню, контекстная панель, док
  `Свойства / Элементы / Слои / Страницы / События / Проверка`,
  включение панелей через меню `Окно` и режим без панелей по `Tab`;
- инструменты текста, изображения, фигур, SVG и календарной сетки;
- создание объекта щелчком или протягиванием рамки, всегда на отдельном слое;
- выделение, перемещение и изменение размера восемью маркерами непосредственно
  на странице;
- удаление, дублирование, отправка на самый верх/низ, drag-and-drop слоёв через
  любое количество позиций;
- выравнивание и распределение нескольких объектов, привязка при перетаскивании
  к странице, safe area и соседним объектам (Alt временно отключает привязку);
- контекстные свойства объекта, типографика, заливка, обводка и импорт локального
  изображения или SVG в рамку;
- четыре встроенные кириллические гарнитуры для печати: древнерусский
  `Ruslan Display`, торжественный `Yeseva One`, книжный `Cormorant Garamond`
  и рукописный `Marck Script`; выбранные начертания одинаково отображаются в
  редакторе и встраиваются в экспортируемый PDF;
- библиотека из 127 векторных элементов: цельные рамки, отдельно нарезанные углы,
  разделители, орнаменты, церковные изображения и символы; поиск, фильтр по разделам,
  вставка на новый верхний слой и свободное перекрашивание SVG;
- собственный парсер `MemoryDays.xml` и независимый расчёт фиксированных,
  пасхальных и специальных правил дат;
- календарная сетка с пятью/шестью неделями, крупной управляемой типографикой,
  церковными сокращениями, ограниченным подбором кегля и явной диагностикой
  переполнения без экранной подписи «ещё» в печатном материале;
- раздельные каналы содержимого XML: праздники и памяти выводятся по умолчанию,
  а чтения, правила венчания и текстовые записи о посте включаются независимо;
- фильтр памятей по рангу: Пасха и двунадесятые, великие, средние и дни
  поминовения; если значимых записей нет, печатаются максимум две помещающиеся
  малые памяти;
- типиконная подача: красные воскресенья и праздники XML-рангов 0–2, чёрные
  обычные дни, отдельный стиль событий монастыря и пять точных SVG-знаков
  типикона, переданных пользователем;
- собственная система из девяти категорий пищи/поста, два полных набора
  пользовательских изображений и индивидуальная замена каждого знака;
- автоматически формируемая легенда, которую можно разместить сверху, снизу
  либо свободно;
- неограниченные ежегодные и разовые события монастыря с полным, кратким и очень
  кратким названием;
- отдельная обложка и три шаблона месячной страницы;
- применение оформления выбранной календарной сетки ко всем месяцам одним действием;
- создание полного проекта: обложка и 12 месяцев;
- IndexedDB-автосохранение, восстановление страницы и состояния панелей, JSON-файл
  проекта, Undo/Redo;
- независимый от DOM многостраничный PDF с физическими MediaBox/TrimBox/BleedBox,
  векторным кириллическим текстом и встроенными шрифтами;
- настраиваемые метки реза в поле вылетов PDF;
- живая предпечатная проверка с переходом от проблемы к странице и объекту;
- проверка эффективного DPI помещённых растровых изображений;
- автоматические тесты геометрии, слоёв, XML, календарных вычислений, компоновки,
  предпечатной проверки и PDF.

## Источник календарных данных

В качестве исходных данных используется `MemoryDays.xml`.

WordPress-плагин:

- не подключается к приложению;
- не является зависимостью;
- его исходный код не переносится;
- его функции и структура кода не копируются.

Парсер XML и календарный движок создаются самостоятельно. Из существующих
материалов используется только структура данных XML и общий принцип вычисления
фиксированных и переходящих дат.

Сам XML и сопровождающий его `MemoryDays.xlsx` содержат только интервалы постов
(`type=10`) и сплошных седмиц (`type=100`), но не содержат отдельного поля для
масла, сухоядения или рыбы. Поэтому степень трапезы рассчитывает независимый
модуль `src/calendar/fasting/fasting-api.ts`. Текущий именованный профиль
`typikon-strict` сопоставлен с опубликованными правилами:

- https://otrada-i-uteshenie.ru/kalendar/
- https://azbyka.ru/days/p-kalendar-postov-i-trapez

## Программный API календаря

Расчёт не зависит от Vue, страницы или PDF и доступен другим модулям через
`src/calendar/index.ts`:

```ts
import {
  calculateFastingDay,
  calculateFastingPeriods,
  createOrthodoxCalendarApiFromXml,
} from "./calendar";

const api = createOrthodoxCalendarApiFromXml(memoryDaysXml);
const year = api.getYear(2027);          // праздники и памяти
const pascha = api.getPascha(2027);      // дата Пасхи
const periods = api.getFastingPeriods(2027);
const fasting = api.getFasting({ year: 2027, month: 3, day: 17 });
```

`calculateFastingDay()` возвращает не только графический идентификатор пищи, но
также период поста, текстовое основание правила, профиль и список источников.
Поминовение хранится отдельным флагом и не уничтожает рассчитанное правило пищи.
Фасад кэширует построенные годы и может применяться в редакторе, экспорте,
серверном обработчике или другом приложении.

## Основные архитектурные правила

1. Источник истины для координат и размеров - миллиметры.
2. CSS-пиксели существуют только в экранном адаптере preview.
3. Печатный документ не зависит от Vue-компонентов и структуры DOM.
4. Vue отвечает только за интерфейс редактирования.
5. Preview, SVG и PDF должны строиться из одной модели документа.
6. Календарные данные, события монастыря, оформление и страницы разделены.
7. Печатная страница не создаётся через `div`, CSS Grid или browser screenshot.
8. Переполнение текста никогда не скрывается молча: оно получает состояние
   `none`, `warning` или `error`.
9. Слои принадлежат отдельной странице; слой пуст либо содержит ровно один
   печатный объект. Новый объект по умолчанию получает собственный слой.
10. Папка слоя не является печатным объектом: она содержит любое число слоёв и
    вложенных папок, а её видимость и блокировка наследуются содержимым.

Подробнее: [ARCHITECTURE.md](./ARCHITECTURE.md).

## Модель проекта

```text
CalendarProject
 ├── PublisherProfile
 ├── Year
 ├── CalendarData
 ├── MonasteryEvents
 ├── StyleTheme
 ├── Assets
 └── DocumentModel
      ├── CoverPage
      ├── January
      ├── February
      ├── ...
      └── December
```

Все печатные элементы имеют базовую геометрию:

```ts
interface LayoutElement {
  id: string;
  type: string;
  x: number;      // mm
  y: number;      // mm
  width: number;  // mm
  height: number; // mm
  rotation: number;
  zIndex: number;
  locked: boolean;
  visible: boolean;
  overflow: "none" | "warning" | "error";
}
```

Специализированные элементы включают текст, изображения, фигуры, SVG,
календарную сетку, текст месяца и автоматически формируемую легенду.

Структура слоёв одной страницы:

```text
Page
 └── Layer tree
      ├── Object layer -> один TextElement
      ├── Folder
      │    ├── Object layer -> один ImageElement
      │    ├── Object layer -> один SvgElement
      │    └── Nested folder
      └── Empty object layer
```

## Структура страницы месяца

- фотография или иллюстрация;
- название месяца;
- интеллектуальная календарная сетка;
- крупные номера дней;
- праздники и памяти святых;
- визуальные обозначения поста и пищи;
- события монастыря;
- текст месяца;
- автоматически сформированная легенда;
- произвольные декоративные элементы.

Обложка является отдельным типом страницы и использует собственный шаблон.

## Основной рабочий процесс

1. В `Свойствах` задайте год, название проекта, издателя и формат страницы.
2. В панели `Страницы` выберите один из трёх шаблонов и создайте 13 страниц.
3. Выберите фоторамку инструментом выделения и поместите свою фотографию.
4. Выберите календарную сетку, настройте шрифты, интерлиньяж, состав данных и
   подписи дней недели. При необходимости примените оформление ко всем месяцам.
   Там же выберите один из двух встроенных наборов из девяти знаков пищи,
   поста и поминовения. Каждый знак при необходимости можно заменить своим файлом.
5. Отредактируйте текст месяца, заголовки и обложку как обычные объекты.
6. Добавьте местные даты в панели `События`.
7. В панели `Элементы` выберите рамку или украшение. Щелчок сразу помещает его
   на новый верхний слой; цвет библиотечного SVG меняется в `Свойствах`.
8. Исправьте замечания панели `Проверка`.
9. Используйте `Файл -> Экспортировать печатный PDF`.

Пустая фоторамка считается предупреждением. Встроенные наборы используют только
переданные пользователем изображения; случайные или сгенерированные изображения
в печатный PDF не подставляются. Легенда каждого месяца содержит только реально
использованные на этой странице знаки. Цитата месяца создаётся только внутри
достаточно большой свободной области календарной сетки; отдельная полоса под
календарём для неё не резервируется.

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Проверки:

```bash
npm run typecheck
npm run test
npm run build
npm run assets:decor
npm run export:sample
```
