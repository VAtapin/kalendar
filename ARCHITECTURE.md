# Архитектура редактора

## Неподвижные принципы

1. Источник истины для печатной геометрии - миллиметры.
2. `DocumentModel` не содержит Vue-компонентов, DOM-узлов или CSS-координат.
3. Vue отвечает только за пользовательский интерфейс редактора.
4. Экранный preview и будущий PDF-экспорт получают одну и ту же независимую сцену.
5. Направляющие, линейки, рамки bleed/trim/safe не являются печатными элементами.
6. Данные календаря, тема оформления и страницы проекта хранятся раздельно.
7. Исходный код WordPress-плагина не является частью проекта и не переносится.
8. `MemoryDays.xml` используется только как источник данных; календарный движок
   реализуется самостоятельно.
9. Слои принадлежат странице. Лист дерева слоёв пуст либо содержит ровно один
   печатный объект; количество слоёв не ограничено.
10. Папка является организационным узлом, содержит любое количество слоёв и
    вложенных папок, может сворачиваться в UI и передаёт скрытие/блокировку потомкам.

## Поток данных

```text
CalendarProject
  -> OrthodoxCalendarApi (dates, feasts, fasting)
  -> DocumentModel (mm)
  -> PageScene (mm)
  -> SVG preview adapter
  -> PDF export adapter
```

`pixelsPerMm` существует только внутри экранного адаптера. Изменение масштаба не
изменяет ни одной координаты документа.

## Реализованные подсистемы

- Vue 3 + TypeScript + Vite.
- Независимые типы `DocumentModel`, `PageModel` и `LayoutElement`.
- Форматы A3/A4/A5/A6 в обеих ориентациях.
- Bleed 3 мм и настраиваемая safe area.
- Экранные линейки с делениями в миллиметрах.
- Чистая функция `buildPageScene`, не зависящая от Vue или DOM.
- Иерархическая модель слоёв и папок с одним объектом на конечный слой.
- Панели издательского интерфейса и контекстные свойства объектов.
- `TextElement`, `ImageElement`, `ShapeElement`, `SvgElement`,
  `CalendarGridElement`, `MonthTextElement` и `LegendElement`, создаваемые и
  редактируемые рамкой в миллиметрах.
- Парсер XML и собственный календарный расчёт без кода WordPress-плагина.
- Публичный `OrthodoxCalendarApi` с кэшем годов: Пасха, праздники, памяти,
  интервалы постов и подробное правило трапезы для любой даты.
- Семантическая типиконная стилизация и отдельный профиль расчёта категорий
  поста; XML задаёт события и ранги, а не подменяет алгоритм трапезы.
- Политика содержимого ячейки отделяет праздники и памяти от чтений, правил
  венчания и служебных записей о посте; каждый канал включается настройкой сетки.
- Экранная и PDF-компоновка текста через общий алгоритм переноса.
- Знаки типикона являются опциональным каналом оформления, по умолчанию
  выключены и при выключении не резервируют место в строках событий.
- Последовательность полного/краткого названия и автоподбор кегля до допустимого
  минимума выполняются одной функцией для preview, PDF и предпечатной проверки.
- Независимый PDF-экспорт с корректными физическими боксами и встроенными
  DejaVu Sans/Serif для кириллицы, включая настраиваемые метки реза.
- Предпечатный анализ модели без чтения DOM.
- IndexedDB-автосохранение и переносимый JSON-снимок проекта.

## Граница предпечатной проверки

`checkCalendarProject()` получает только `CalendarProject` и рассчитанный год.
Она проверяет пустые assets, отсутствующие картинки пищи, переполнение текста и
календарных строк, выход за trim/safe area, достаточность вылетов для меток реза и
отсутствие сетки на странице месяца.
Панель Vue лишь отображает результат и переводит пользователя к объекту.
