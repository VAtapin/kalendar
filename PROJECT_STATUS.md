# Состояние проекта

- Календарного HTTP API и календарного серверного runtime в Kalendar нет. Прежние календарные маршруты возвращают 404. Единственный поставщик публичных календарных данных, чтений, служб и икон — Bible Desktop. Внутренние функции аккаунтов, хранения, общих ссылок, заказов и печати сохранены.
- Главный редактор, администраторский предпросмотр и конструктор сеток используют `/api/v1/calendar/editor-year` BibleDesktop через единый адаптер. Экран и PDF используют готовые события, переводы и оба профиля поста. Локальные расчёты праздников/поста/чтений исключены из production-бандла; справочное ядро оставлено для аудитов и тестов.
- Полный проверенный снимок сохраняется в документе, серверных проектах, архивах, восстановлении и шаблонах. Сохранённая версия не обновляется автоматически; явное обновление создаёт резервную копию. Проверяются схема, полнота года и SHA-256. Ошибка сети/429/контрольной суммы не подменяет сохранённые данные. Частные монастырские события и дизайн остаются локальными. Публичный кэш отделён от приватной IndexedDB; её версия 4 не менялась. История использует пул снимков.
- BibleDesktop добавил новый контракт и явный перенос памятей 29 февраля на 28 февраля в невисокосные юлианские годы: `c91448b4dbea7338d5fc47a8fa3c9d5d6f57e052`, Add editor calendar snapshots, main → origin/main. my_bible_app подтвердил отсутствие пересечения: его day/month/service сохранены, новый endpoint он не использует.
- Резервные копии: исходная `tmp/backups/Kalendar-20261008-140402` и перед переходом редактора `tmp/backups/Kalendar-editor-api-20261008`, включая проверенные Git bundles. Они приватные, не включаются в Git. Пользовательские PNG и посторонние artifacts исключены из commit.
- Проверки текущего перехода прошли: Vitest 77 файлов / 545 тестов; typecheck и production build; production bundle без локального расчётного ядра; пять настоящих годовых снимков ru/de/cu/uk/pl (365 дней, события, названия и оба профиля); сохранение/открытие/история снимков на PHP-сервере для всех пяти языков; аккаунты, междоменная сессия, заказы; старые календарные маршруты 404; настоящий серверный CMYK PDF/X-1a. Созданы RGB PDF на ru/de/cu, по 13 страниц; остаются предупреждения о невыбранных фото и неподдерживаемом прямым PDF встроенном SVG, ошибок шрифтов нет.
- Браузерные проверки: отдельный API-сценарий сохраняет и открывает 13 страниц при заблокированном API без XML. Общий набор дал 18 успешных и 4 неуспешных сценария; два сценария фото/сохранения/справки после актуализации прошли отдельно. Два оставшихся сценария входа/публикации/общей ссылки ожидают прежнюю passwordless-форму; весь общий набор не объявляется успешным. Реальные backend-проверки соответствующих сессий/аккаунтов прошли.
- WordPress Calendar Workshop остаётся 1.3.71: 22 блока, 16 оформлений, иконы/Monomakh/декор, ZIP в artifacts и public/downloads. Предыдущая миграция HTTP API опубликована владельцем и проверена 200/404/ZIP; установка ZIP в WordPress отдельно пока не подтверждена. Текущий переход редактора на production ещё не опубликован.
- Важно для публикации: новый editor-year на production BibleDesktop пока вернул HTTP 404. Сначала обновить BibleDesktop до c91448b4, затем Kalendar; после npm ci и до build выполнить `npm run check:editor-api`. Проверка использует production PUBLIC_API_URL и при ошибке останавливает публикацию. Локальный альтернативный bibel.cloud не разрешился в DNS; .env не менялся, доступность настроенного на сервере поставщика нужно подтвердить preflight.
