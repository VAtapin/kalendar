# Состояние проекта

## Реализовано

- Основной календарный сайт и публичный API работают из репозитория `Kalendar`.
- На главной странице опубликован первый готовый календарь Свято-Георгиевского мужского монастыря в Гётчендорфе на 2027 год: это одна карточка с выбором русской, немецкой или украинской PDF-версии. Структура блока рассчитана на добавление следующих готовых календарей.
- Публичный исходный репозиторий WordPress-плагина — `VAtapin/wp_orthodox_calendar`; подготовлена версия 1.3.62 и ZIP `orthocal-1.3.62.zip` для сайта Kalender. `Plugin URI` ведёт на страницу `/calendar-api`, а `Author URI` — на `atapin.de`, поэтому заголовок соответствует требованию WordPress.org о разных URL. Внутренняя версия подключаемых JS/CSS совпадает с заголовком плагина, поэтому обновление сбрасывает кэш старого сценария галереи. При пустом `text_language` библиотеки выбирают редакцию с наибольшим числом материалов, а явный выбор языка сохраняется. Нажатие на икону дня всегда перехватывается плагином, а не темой: в одном окне вверху находятся миниатюры изображений выбранного образа, стрелки, свайп и клавиатура листают только их, а все остальные образы дня выбираются маленькой лентой внизу. `icon_limit` ограничивает только карточки блока, но не галерею.
- Версия 1.3.39 собрана; предпросмотр защищён от запоздалых ответов при выборе картинок, устранена автоматическая подмена `cu` на `cu-civil`.
- Версия 1.3.40 подавляет картинку поста при `no-fast` и проверяет все наборы на постной дате.
- Версия 1.3.41 заменяет относительный размер картинок поста вводом высоты в пикселях; ширина рассчитывается браузером по пропорциям. Старые `small`, `medium`, `large` сохранены для уже вставленных шорткодов.
- Версия 1.3.42 размещает управление переводом и размером чтений либо на странице, либо внутри всплывающего окна в соответствии с `reading_open`; ползунок работает в обоих режимах.
- Версия 1.3.43 выводит перед текстом чтения только номер стиха, без повторения OSIS-кода книги и главы.
- Версия 1.3.44 добавляет заголовок при переходе к следующей главе и открывает окна богослужебной библиотеки в полный размер окна чтений.
- Версия 1.3.48 выводит ползунок размера текста во всех разделах библиотеки и снимает ограничение ширины колонки в большом окне.
- Версия 1.3.48 отменяет ошибочное разделение файлов шрифтов: `cu` и `cu-civil` снова используют один Monomakh Unicode через исходный загрузчик FontFace.
- Старые автоматически созданные заголовки месяцев без `semanticRole` теперь распознаются и переводятся вместе с выбранным языком календаря; вручную изменённые заголовки не перезаписываются.
- Автоматические названия месячных страниц и текстовых заголовков теперь содержат только месяц: год остаётся в названии календаря, а старые `Март 2027` мигрируют в `Март` с переводом при смене языка; ручные названия не меняются.
- `Rurintania.ttf` расширен глифами `ä Ä ö Ö ü Ü ß`; старые проекты продолжают использовать то же семейство, а PDF встраивает расширенный шрифт целиком, чтобы новые глифы не терялись при subset.
- Подпись вставленной иконы остаётся отдельным текстовым объектом: её можно самостоятельно выбрать, переместить, изменить размер и шрифт; изменение размера иконы не меняет кегль подписи.
- В редактор добавлен локальный Ponomar — церковнославянский Unicode-шрифт с SIL OFL-лицензией; он встраивается и в PDF.
- Установочный архив 1.3.58 добавлен в `artifacts` и `public/downloads`; серверная сборка публикует его на сайте календаря.
- Страница `/calendar-api`, публичная документация и проверочный скрипт указывают на актуальный архив WordPress-плагина 1.3.58.
- Версия и имя ZIP на странице `/calendar-api` теперь подставляются на сборке из заголовка `wordpress/orthocal/orthocal.php`; сборщик плагина и проверка страницы используют тот же источник.
- Стандартное серверное обновление Kalendar всегда выполняет `nodenv local 22`, `npm ci --include=dev` и `npm run build` после fast-forward pull; PHP CLI и общий Plesk PATH не добавляются.
- Страница API календаря и её Markdown-инструкция ведут на постоянный адрес GitHub Release `releases/latest/download/orthocal.zip`; workflow репозитория плагина создаёт этот ZIP при теге версии. До первого тега ссылка ещё не отдаёт файл.
- На странице `/calendar-api` добавлен отдельный раздел `Church Slavonic Translator`: бесплатный и ключевой режимы, корпусный и кэшированный перевод, копирование для Word, системные требования, ссылка на релиз `1.0.0` и репозиторий.
- В плагине разделены русские тропари и кондаки, а список языков ограничивается доступными редакциями.
- Общий рендерер полного произведения и справочного песнопения сохраняет раздельные языковые атрибуты `cu` и `cu-civil`; обе церковнославянские редакции используют Monomakh Unicode.
- Подготовлен PowerShell-загрузчик немецких текстов Orthodoxia.de и импортный корпус из 19 страниц.
- Веб-календарь переведён на верхнюю закрытую панель фильтров; месяц стал компактнее, а окно дня шириной около 85% открывается сразу и догружает службу отдельно.
- Веб-календарь получает полный каталог икон Bible Desktop по `month_day` (`MM-DD`), показывает компактные миниатюры перед разделом «Святые и праздники», а имена святых остаются обычным текстом без лишних ссылок. Каждый образ открывается отдельно: в единственном окне сначала показано описание с лентой миниатюр над ним, а стрелки, свайп и клавиатура переключают только изображения выбранного образа.
- Calendar API сопоставляет каждый образ с событием дня по двум значимым фрагментам названия либо подписи празднования Bible Desktop и публикует `calendarRank`. Сначала идут образы Спасителя, затем Богородицы, затем события по типиконному рангу; несопоставленные карточки остаются в конце. XML остаётся источником рангов, Bible Desktop — источником образов и их дат.
- WordPress-плагин 1.3.59 и веб-календарь получают полный каталог икон дня и все изображения каждого образа. `icon_limit` ограничивает только видимые обложки, не галерею. Под обложкой показаны имя, компактные даты из API Bible Desktop (например, `7 февраля (пер.)`) и одна цифра — число изображений; длинное описание остаётся только в карточке просмотра. В WordPress и веб-календаре описание, лента миниатюр и полное изображение сменяют друг друга в одном окне выбранного образа; в WordPress лента остальных образов дня остаётся внизу этого же окна. WordPress создаёт локальные 96px WebP/JPEG-миниатюры, а веб-календарь кэширует такие же варианты на сервере. Полные изображения запрашиваются только при переходе от описания к изображению.
- Веб-календарь исправляет повторное отображение старой картинки при открытии нового образа, загружает церковнославянский шрифт для кириллических названий и размещает стрелку фильтров сразу после заголовка. Ячейки Пасхи и великих/средних праздников подсвечиваются, показывают знак Типикона, а дни без поста не занимают пустую строку.
- Веб-календарь отмечает текущую дату зелёной рамкой во всех представлениях. В месяце показывается от одной до пяти памятей по выбору пользователя (по умолчанию три); настройка сохраняется в URL. Пост выделен заметнее, а служебная надпись «Календарь готов.» после загрузки убрана.

## Текущее состояние и решения

- Ветка разработки: `main`, upstream: `origin/main`.
- Печатный экспорт редактора: пользователь выбирает бумагу и ICC-профиль; страницы календаря отрисовываются при 300 dpi и напрямую собираются серверным Node.js в CMYK PDF/X-1a:2001 (PDF 1.3). Прозрачности и эффекты сведены в непрозрачные изображения страниц, промежуточного PDF и Ghostscript в новом экспорте нет. Готовые PDF календаря 2027 года не пересоздавались. Связанный commit: `Build print PDF directly from calendar pages`.
- При снимке страницы печатный экспорт теперь явно встраивает используемые шрифты SVG, включая загруженные пользователем; CMYK JPEG сохраняется при качестве 90 и 300 dpi для уменьшения PDF. Исправление готово локально, production пока не обновлён.
- В том же диалоге доступен стандартный RGB PDF 1.7: прежний векторный экспортёр создаёт файл без CMYK-преобразования, сервер сохраняет его и выдаёт ссылку без требования ICC-профиля. CMYK PDF/X-1a остаётся отдельным вариантом.
- Богослужебный корпус и изображения икон фактически обслуживаются API проекта Bible Desktop.
- Для иконок календаря используется каталог Bible Desktop `/api/calendar/icons?month_day=...&with_images=1`, а не сокращённый `/api/calendar/day`: это сохраняет все карточки, все изображения и опубликованные даты празднования. API Kalendar связывает их с рассчитанными XML-событиями только при проверяемом совпадении двух значимых фрагментов.
- Долгие скачивания, массовая обработка, импорт и проверки следует выполнять отдельными PowerShell- или серверными скриптами.
- Церковнославянская редакция `cu-civil` является отдельным вариантом отображения и не должна получать традиционный шрифт.
- `cu` и `cu-civil` — отдельные языковые версии; подстановка одной вместо другой и преобразование текста недопустимы.
- Обычный WordPress-плагин работает без регистрации и ключа: он передаёт открытый `X-Calendar-Client: orthocal-wordpress`. API разрешает этому режиму только `/day`, `/month`, `/year`, `/pascha` и `/upcoming`, проверяет параметры и диапазон 1900–2200, применяет серверный кэш и лимиты 90 запросов в минуту / 5000 в сутки на IP WordPress-сервера. Заголовок не является учётными данными; `/service` и `/calendar-texts` по-прежнему требуют API-ключ.
- Страница `/calendar-api` синхронизирована с моделью плагина: установка работает без ключа, открытый заголовок объяснён как не-секретный идентификатор с ограниченным allowlist, а API-ключ описан только как необязательный расширенный доступ.
- `Church Slavonic Translator` остаётся отдельным репозиторием `VAtapin/wp_cu_translator`; публикация релиза GitHub не включает отправку в WordPress.org.

## Известные проблемы

- Немецкий корпус Orthodoxia.de импортирован с навигационным текстом страниц; все 19 немецких импортов должны оставаться снятыми с публикации до исправления извлечения и сопоставления с существующими произведениями.
- Локально присутствует большой незакоммиченный корпус икон и связанных артефактов. Эти файлы принадлежат текущей пользовательской работе и не должны попадать в посторонние коммиты.
- Публичный Bible Desktop API на 12.09.2026 не содержит `cu` у 38 канонов, 3 акафистов, 14 произведений horologion-appendix и 14 молитв; справочник calendar-texts для `cu` возвращает 0 записей. В Часослове `cu` есть у 21 из 35 произведений. Отсутствующие версии нельзя исправить CSS.
- Знаки икры и полного воздержания общие для всех наборов. При `no-fast` календарь и плагин не выводят картинку поста.
- API службы календаря пока публикует проверенный недельный цикл и расширенные формулы, но собственные праздничные тексты остаются без привязки (`properAssignments` пустой); веб-интерфейс явно сообщает об этом ограничении.
- PHP CLI для локальных проверок найден в `D:/Projekte/Kloster-PAY/tmp/php84/php.exe`; тестовый ini задаёт extension_dir, mbstring, openssl и fileinfo. Локальные WordPress-тесты работают с pdo_sqlite/sqlite3.
- Новый прямой печатный экспорт ещё не проверен на production. PDF содержит растровые страницы 300 dpi, в том числе текст. Для обработки через PHP-FPM требуется доступный Node.js из `dist/api/calendar-runtime.json`; Ghostscript новому экспорту не нужен.
