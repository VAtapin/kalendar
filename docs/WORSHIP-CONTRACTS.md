# Контракты читателя служб

Сверено 02.11.2026 с локальными контроллерами BibleDesktop. Это перечень
подключений, а не утверждение полноты текстов на всех датах.

| Служба | Существующий контракт | Подключение Kalendar |
| --- | --- | --- |
| Первый, Третий, Шестой, Девятый часы | `services/{office}`, `templates/{office}`, `assignments/{office}`; CU `profile=ordinary-clergy` | Постоянная основа и проверенные дневные операции; complete только после проверки контекста, источников и итогового хеша |
| Литургия | `services/liturgy`, `templates/liturgy`, `assignments/liturgy`; CU `mode=fixed` | Основа Иоанна Златоуста и подтверждённые дневные секции; целая Литургия пока не утверждена |
| Утреня, вечерня | `templates/{office}`, `assignments/{office}`; CU `sequence=standalone|vigil` в assignments | Исходный книжный текст с явным предупреждением: служба дня не составлена |
| Царские часы | Отдельные `services/royal-hours`, `templates/royal-hours`, `assignments/royal-hours` | Пока не подключены: требуется отдельный выбор практики и ветви, проверка доступности и принятие профиля |
| Повечерия, полунощницы, Изобразительны | В проверенных контроллерах нет самостоятельных поддержанных office IDs | Не добавлять пункты, ведущие на отсутствующие маршруты |
| Литургии Василия Великого и Преждеосвященных Даров | `templates/liturgy`, `assignments/liturgy`, CU `mode=fixed`, явный `rite` | Отдельный выбор чина; только постоянная основа с обязательными незаполненными местами. Дата — дата запроса, не подтверждение назначения |

Царские часы требуют `language=cu`, `sequence=linked`,
`clergy=priest-and-deacon`, `polychronion=outside-hours`,
`practice=cathedral-post-eve-liturgy-vespers`; mode — `theophany|nativity`.
Для templates требуется branch `with-liturgy|transferred-friday`.
Нельзя автоматически переносить эти параметры на другие службы.

## Полнота в интерфейсе

Читатель различает полную службу, частичный состав, книжную схему, загрузку,
ошибку дневных назначений и отсутствие назначения. Наличие полного книжного
текста не считается подтверждением службы на выбранную дату.

Незаполненные узлы подсчитываются отдельно. Опубликованные причины позволяют
отличить неподтверждённое дневное назначение от отсутствия проверенных местных
данных. Неизвестная причина получает нейтральное сообщение; внутренние коды и
произвольный текст ошибок в интерфейс не выводятся. Статус и причины остаются
в печатном содержимом вместе с исходным текстом.

## Дополнительные Литургии

Selector — `rite=basil-great|presanctified`, только CU `mode=fixed`.
Преждеосвященные требуют явного `midLentBranch=before-mid-lent-wednesday`
или `from-mid-lent-wednesday`. Клиент не вычисляет ветвь по дате.
Дата передаётся только в assignments; храм, sequence и calendarStyle в этой
GET-ветви не поддержаны и не передаются. Старый выбор Иоанна Златоуста не добавляет
selector и сохраняет прежние дневные контракты.

Ответ находится непосредственно в `data`. Новый клиент проверяет собственные
template/profile IDs, редакцию, версии, источники, обязательные slots/contracts,
фиксированный хеш и false-флаги допуска полной службы. Assignments допускается
только как `partial`, с точным `requestedContext`, всеми missing и пустыми
operations. Постоянных блоков — 728/598/634, обязательных мест — 36/30/30.
Новые основы не пропускаются через прежнюю валидацию полного дневного состава.

Условные шаблоны показаны в отдельном закрытом разделе, не применены к основному
тексту. Проверяются их фиксированные слова, хеши, незаполненные места и отсутствие
подтверждённого выбора/числа повторений. Печать использует тот же основной текст,
сохраняет предупреждения и не раскрывает условные варианты автоматически.
Новые UI-надписи имеют RU/DE варианты; исходные слова не переводятся словарём UI.
Чин и ветвь сохраняются в ссылке. Ошибка загрузки assignments сохраняет
проверенную постоянную основу и помечает назначения как недоступные.

Сначала опубликовать соответствующий backend-контракт и его источники, затем
Kalendar. Проверка без браузера и без изменения данных сервера:

```bash
node scripts/test-additional-liturgy-api.mjs
```

Она запрашивает три профиля, проверяет хеши, число блоков/мест, отображение
читателя и HTTP 422 неподдержанного храма. Для изолированных реальных ответов
Laravel API поддержан `--responses <capture.json>`; синтетические fixtures не
являются подтверждением доступности production API.

Для набора отдельных verbatim API-ответов backend поддержан
`--manifest <manifest.json>`. Проверяются HTTP-статусы, длины и SHA-256 всех
файлов; дата берётся из фактического requestedContext каждого ответа. Проверка
manifest подтверждает положительные ответы; отрицательные запросы проверяются
при публичном запуске или через сохранённый rejectedTemple в --responses.

## Буквальные местные имена дополнительных Литургий

Отдельная форма вводит именительный/дательный падеж священника и диакона
для Василия и только именительный для двух ветвей Преждеосвященных. Пустые
поля не выводятся из других падежей. Применение требует явного подтверждения;
редактирование имени или храма снимает его и отменяет ожидающий запрос.
Значения живут только в памяти текущего читателя, не входят в URL, календарное
состояние или browser storage. Смена читателя и очистка удаляют их.

После проверки доступности действующая форма раскрыта. Она объясняет область
ввода, показывает точные введённые падежные формы перед отправкой, напоминает
о незаполненных полях и сообщает об успешном применении. Preview не составляет
новую молитвенную формулу и не склоняет имена; готовый текст берётся только из
проверенного POST-ответа. Редактирование/очистка убирают подтверждение и сообщение
об успехе; preview очищается вместе с именами. Отправка на сервер происходит
только при применении, транспорт и приватные границы не меняются.

В читателе местные места имеют понятные подписи: священноначалие, местоположение,
приход/монастырь и имена служащих. `contractKind=evangelist/appointed-saint`
обозначает дневное назначение, даже когда старый reason содержит local-context.
Эти имена не предлагаются как личные данные прихода. Счётчик missing сохраняется.
В settled partial-составе сводка отдельно считает данные храма, назначения дня
и прочие условия по тем же причинам/контрактам, что объяснения пробелов.
Кнопки ведут к первому соответствующему месту либо к уже доступной форме имён;
они не отправляют данные и не скрывают остальные места. Устаревшие переходы
после смены состава игнорируются. Числа групп сохраняются в печати и PDF,
элементы управления не печатаются. Это числа мест в тексте, а не полей ввода.
Текущий POST принимает Basil/Presanctified; отдельный ввод священноначалия,
местоположения и приход/монастырь для Chrys требует расширения проверенного
backend-контракта. Неработающие поля и автоматические подстановки не добавляются.

Runtime activation guard сначала проверяет выбранный POST-контракт запросом
с параметрами чина и `localContext:null`, без имён. Форма открывается только
при HTTP422/private/no-store с единственной ошибкой localContext. 404/405,
ошибки чина, сети и кэшируемые ответы оставляют форму скрытой, сохраняя
проверенную GET-основу. Проверка ограничена тремя секундами и отменяется при
смене читателя. До публикации POST рабочий сайт продолжает показывать основу
без недействующей формы.

Транспорт — POST JSON на прежний ресурс `/api/v1/liturgical/assignments/liturgy`,
без query. Тело: language/mode/rite, для Преждеосвященных midLentBranch,
date/templateVersion, temple и localContext. Последний содержит schemaVersion=1,
templeProfileId, confirmedLiteralForms=true и people.celebrant/deacon.forms.
Нормализуются только структура и порядок полей; строки не склоняются, не
транслитерируются, не обрезаются и не заменяются. GET остаётся прежним.

Приём имён отделён от исходниковых verifiedSections: проверяются userSections
policy/inputHash/private/origin=user-provided, source/currentAuthority=false,
точные разрешённые targets, sourceContract/sourceNode hashes, роли и literal
segments. Для смешанных формул sourceFrame/sourcePieces/segmentOrigins позволяют
восстановить исходные окружающие слова и проверить текстовый хеш, заменяя имя
обратно только засвидетельствованным маркером. Общий проверяющий модуль —
`worship-user-literal.js`; отдельный сервис обязан сначала связать свой
разрешённый target и ввод, общий модуль не даёт допуска новых служб или slots.

Четыре/два/два заполнения оставляют 32/28/28 обязательных мест и status=partial.
Местные имена обозначены как пользовательские в читателе и печати. Форма ввода
в печать не попадает; сами применённые слова печатаются из того же body.
Ошибка/редактирование/очистка возвращают исходную проверенную основу, а поздний
ответ не заменяет новый выбор. Роли, громкость и число повторений не выводятся
из имён и не угадываются.

До сборки Kalendar backend должен иметь опубликованный POST-контракт. Проверка
готовности выполняет CORS OPTIONS и заведомо невалидный POST `{}` без имён,
проверяет HTTP422 и private/no-store; данные в базу она не записывает:

```bash
node scripts/check-local-liturgy-endpoint.mjs
```

Проверка окончательных локальных AppKernel captures без сетевых запросов:

```bash
node scripts/test-local-liturgy-api.mjs --manifest <local-manifest.json> --templates <fixed-manifest.json>
```
