# Контракты читателя служб

Сверено 02.11.2026 с локальными контроллерами BibleDesktop. Это перечень
подключений, а не утверждение полноты текстов на всех датах.

| Служба | Существующий контракт | Подключение Kalendar |
| --- | --- | --- |
| Первый, Третий, Шестой, Девятый часы | `services/{office}`, `templates/{office}`, `assignments/{office}`; CU `profile=ordinary-clergy` | Постоянная основа и проверенные дневные операции; complete только после проверки контекста, источников и итогового хеша |
| Литургия | `services/liturgy`, `templates/liturgy`, `assignments/liturgy`; CU `mode=fixed` | Основа Иоанна Златоуста и подтверждённые дневные секции; целая Литургия пока не утверждена |
| Утреня, вечерня | `templates/{office}`, `assignments/{office}`; CU `sequence=standalone|vigil` в assignments | Исходный книжный текст с явным предупреждением: служба дня не составлена |
| Царские часы | Отдельные `services/royal-hours`, `templates/royal-hours`, `assignments/royal-hours` | Пока не подключены: требуется отдельный выбор практики и ветви, проверка доступности и принятие профиля |
| Повечерия, полунощницы, Изобразительны | В проверенных контроллерах нет самостоятельных поддержанных office IDs | Не добавлять пункты, ведущие на отсутствующие маршруты |
| Литургии Василия Великого и Преждеосвященных Даров | `templates/liturgy`, `assignments/liturgy`, CU `mode=fixed`, явный `rite` | Отдельный выбор чина; только постоянная основа с обязательными незаполненными местами. Дата — дата запроса, не подтверждение назначения |

Царские часы требуют `language=cu`, `sequence=linked`,
`clergy=priest-and-deacon`, `polychronion=outside-hours`,
`practice=cathedral-post-eve-liturgy-vespers`; mode — `theophany|nativity`.
Для templates требуется branch `with-liturgy|transferred-friday`.
Нельзя автоматически переносить эти параметры на другие службы.

## Полнота в интерфейсе

Читатель различает полную службу, частичный состав, книжную схему, загрузку,
ошибку дневных назначений и отсутствие назначения. Наличие полного книжного
текста не считается подтверждением службы на выбранную дату.

Незаполненные узлы подсчитываются отдельно. Опубликованные причины позволяют
отличить неподтверждённое дневное назначение от отсутствия проверенных местных
данных. Неизвестная причина получает нейтральное сообщение; внутренние коды и
произвольный текст ошибок в интерфейс не выводятся. Статус и причины остаются
в печатном содержимом вместе с исходным текстом.

## Дополнительные Литургии

Selector — `rite=basil-great|presanctified`, только CU `mode=fixed`.
Преждеосвященные требуют явного `midLentBranch=before-mid-lent-wednesday`
или `from-mid-lent-wednesday`. Клиент не вычисляет ветвь по дате.
Дата передаётся только в assignments; храм, sequence и calendarStyle в этой
ветви не поддержаны и не передаются. Старый выбор Иоанна Златоуста не добавляет
selector и сохраняет прежние дневные контракты.

Ответ находится непосредственно в `data`. Новый клиент проверяет собственные
template/profile IDs, редакцию, версии, источники, обязательные slots/contracts,
фиксированный хеш и false-флаги допуска полной службы. Assignments допускается
только как `partial`, с точным `requestedContext`, всеми missing и пустыми
operations. Постоянных блоков — 728/598/634, обязательных мест — 36/30/30.
Новые основы не пропускаются через прежнюю валидацию полного дневного состава.

Условные шаблоны показаны в отдельном закрытом разделе, не применены к основному
тексту. Проверяются их фиксированные слова, хеши, незаполненные места и отсутствие
подтверждённого выбора/числа повторений. Печать использует тот же основной текст,
сохраняет предупреждения и не раскрывает условные варианты автоматически.
Новые UI-надписи имеют RU/DE варианты; исходные слова не переводятся словарём UI.
Чин и ветвь сохраняются в ссылке. Ошибка загрузки assignments сохраняет
проверенную постоянную основу и помечает назначения как недоступные.

Сначала опубликовать соответствующий backend-контракт и его источники, затем
Kalendar. Проверка без браузера и без изменения данных сервера:

```bash
node scripts/test-additional-liturgy-api.mjs
```

Она запрашивает три профиля, проверяет хеши, число блоков/мест, отображение
читателя и HTTP 422 неподдержанного храма. Для изолированных реальных ответов
Laravel API поддержан `--responses <capture.json>`; синтетические fixtures не
являются подтверждением доступности production API.

Для набора отдельных verbatim API-ответов backend поддержан
`--manifest <manifest.json>`. Проверяются HTTP-статусы, длины и SHA-256 всех
файлов; дата берётся из фактического requestedContext каждого ответа. Проверка
manifest подтверждает положительные ответы; отрицательные запросы проверяются
при публичном запуске или через сохранённый rejectedTemple в --responses.
