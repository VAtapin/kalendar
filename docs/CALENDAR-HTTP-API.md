# Календарь через API Bible Desktop

Kalendar — редактор печатных календарей и клиент Bible Desktop. Собственного
календарного HTTP API, тарифов и ключей в Kalendar нет. Старые маршруты
`/api/v1/calendar`, `/calendar-demo`, `/calendar-texts`, `/calendar-access`
и серверная богослужебная библиотека удалены и возвращают HTTP 404.
Вход, сохранение макетов, шаблоны сеток, PDF и заказы редактора сохраняются.

## Единственный поставщик

```text
https://bible-desktop.com/api/v1/calendar/
```

Адрес поставщика задаётся `PUBLIC_API_URL=https://bible-desktop.com` в `.env`
Kalendar и полем «Адрес API» в WordPress-плагине. Корень указывается без `/api`.
Веб-календарь выполняет GET-запросы прямо к Bible Desktop, без посредника Kalendar.
Редактор, его предпросмотры и PDF используют проверенный годовой снимок
BibleDesktop `/api/v1/calendar/editor-year`; исходное XML-ядро остаётся только
для тестов и аудитов и не попадает в production-бандл.
Хранение и обновление снимков: [Календарные данные редактора](EDITOR-BIBLE-SNAPSHOTS.md).

| GET-маршрут Bible Desktop | Ответ |
| --- | --- |
| `today` | `{metadata, day}`; сегодня по Europe/Berlin |
| `day?date=2026-10-08&lang=uk&profile=typikon-strict` | `{metadata, day}` |
| `month?year=2026&month=10&view=summary` | `{metadata, year, month, pascha, days}` |
| `year?year=2026&view=summary` | `{metadata, year, pascha, days}` |
| `pascha?year=2026` | `{metadata, year, pascha}` |
| `upcoming?date=2026-10-08&limit=5&filter=main` | `{metadata, from, until, items}` |
| `service?date=2026-10-08&office=sixth-hour&expansion=full` | План службы Bible Desktop |

Поддерживаются годы 1900–2200, календарные языки `ru, cu, de, uk, pl`, профили
`typikon-strict, parish`. Гражданская дата — григорианская; старый стиль —
отдельное поле. Публичные маршруты ограничены 30 запросами в минуту. Авторизация,
квоты и доступность редакций текста определяются Bible Desktop; старый ключ
Kalendar не переносится в другой сервис.

Для явного `service?lang=...` язык означает редакцию текста: `cu`, `cu-civil`
или `ru`. Веб-календарь использует автоматический контракт schema 2:
`text_policy=calendar-language-v1&calendar_lang=ru`, независимо от языка
интерфейса. Он выбирает для каждого произведения церковнославянский оригинал,
затем гражданскую запись, затем русский. `calendar_lang=ru` здесь задаёт
единый приоритет богослужебных редакций; язык календарных событий не меняется.
Шрифт определяется возвращёнными `language`/`orthography`: традиционный
церковнославянский — встроенный Ponomar, гражданская запись и русский —
встроенный DejaVu Serif с корректным позиционированием ударений. Названия
церковнославянского календаря по-прежнему используют Monomakh Unicode.
Ответ старой schema 1 не принимается за автоматический выбор.
В параметре `month` используется целое число без ведущего нуля.

## Богослужение сегодня в веб-календаре

Кнопка «Богослужение сегодня» и переход из карточки дня открывают полноценную
страницу чтения в том же приложении. Прямая ссылка:

```text
/web-calendar?view=worship&date=2025-11-09&office=third-hour&temple=george-victorious&lang=ru
```

Доступны `first-hour`, `third-hour`, `sixth-hour`, `ninth-hour`, `liturgy`,
`matins` (утреня), `vespers` (вечерня).
Публичный поставщик: `GET /api/v1/liturgical/templates/{office}` и
`GET /api/v1/liturgical/assignments/{office}` Bible Desktop. Сначала без даты
загружается опубликованная основа, затем её дневные назначения. В назначения
передаются `templateVersion`, гражданская `date`, `calendarStyle=julian`
и выбранный `sequence`. Для первого/девятого Часов и Литургии передаётся
подтверждённый храмовый профиль `temple`; третьему/шестому Часам этот параметр
не передаётся согласно текущему контракту. Пресеты храма: Георгий, Николай,
Преображение, Успение. Выбор храма сохраняется при переключении службы.

Режимы: первый — после утрени с совершённым отпустом и явным выбором
заключительного песнопения; третий — самостоятельно; шестой — после третьего;
девятый — самостоятельно или перед вечерней с выбором храм/притвор;
Литургия — по серверному назначению дня; утреня/вечерня — самостоятельно или
в составе всенощного бдения (sequence=vigil). Эти параметры сохраняются в URL.

Для всех семи служб есть отдельный «Язык текста», независимый от
языка интерфейса. Выбор `textLanguage=auto|cu|cu-civil|ru` сохраняется в прямой ссылке.
По умолчанию auto запрашивает `language=cu`, затем `cu-civil`, затем `ru` только при
явном ответе об отсутствии редакции (текущий контракт: HTTP422 с единственным
errors.language=[validation.in]). При явном выборе языка подстановка запрещена.
Ошибки сети/доступа/проверок не меняют редакцию. Основа проверяется на совпадение
фактического языка, назначения запрашиваются с тем же language и templateVersion.
На 13.10.2026 опубликованы traditional cu источники всех семи служб в формате
source-bound-template/source-outline. Клиент принимает этот формат также для
Часов, утрени и вечерни: прежнее ограничение только Литургией вызывало ошибку
загрузки после публикации cu. Утреня и вечерня сейчас поддерживают только cu.
Шрифт каждого блока
определяется фактическим языком/орфографией источника, включая дневные вставки.
Приоритет карточки дня остаётся `cu → cu-civil → ru`; шрифт не создаёт отсутствующую
traditional редакцию. Порядок блоков, повторы, красные рубрики и параллельные
молитвы сохраняются. Доступны сворачиваемое оглавление и размер текста.

Публичная `fixed-complete` основа Часа показывается сразу и остаётся видимой при
ошибке назначений, включая HTTP 409/422/429/503. Неопределённые slots отмечаются
в тексте. Применяются только явные серверные `fill`, `replace`, `remove` с проверкой
версий, источников, контекста и адресуемых узлов. Метаданные occurrence привязываются
без изменения постоянного текста. `complete` требует отсутствия дыр и совпадения
SHA-256 собранных блоков; partial не выдаётся за готовую службу дня.
Доступность обновляется при открытии, смене контекста или повторной проверке без
списка разрешённых дат. Новые назначения поддержанных служб не требуют выпуска клиента.

Карточка дня содержит отдельные раскрываемые группы назначенных вставок
(`insert=true`) и справочных текстов. Одни и те же properAssignments, уже
включённые в assignments, не выводятся повторно; идентичность определяется
по ID, не по заголовкам. Справочный тропарь нельзя самовольно назначить в Час.
Верхний поясняющий абзац веб-календаря удалён.

Контракт согласован с BibleDesktop и подключён. На 12.10.2026 основы всех четырёх
Часов доступны; дневные troparion/kontakion slots пока не подтверждены. Третий час
09.11.2025 проверен как complete с совпадением хеша полного серверного результата.
Traditional cu основы всех семи служб пока возвращают `source-outline`, не cleanTemplate:
показываются все исходные абзацы с явной пометкой невыбранных дневных вариантов.
Утреня содержит329, вечерня167 абзацев; Литургия584 в cu и585 в cu-civil.
`sourceAnchor` не считается разрешением
на вставку или выбор условных вариантов. Полная дневная сборка Литургии остаётся
задачей BibleDesktop; даже not-appointed не скрывает книжный источник. Повечерия,
полунощницы и Изобразительны требуют отдельного опубликованного модульного
контракта; их существование в библиотеке не означает готовую сборку дня.

В чтениях номер зачала
показывается только для `reading.lectionary.status=exact-reference-match`,
`basis=exact-source-coordinates` и одной идентичности книга+номер. Неоднозначные
совпадения и псалмы номера не получают; номера не доказывают соответствие
нумерации стихов другого перевода. WordPress runtime/ZIP этой правкой не меняются.

```bash
curl 'https://bible-desktop.com/api/v1/calendar/day?date=2026-10-08&lang=uk&profile=typikon-strict'
```

Другие прямые маршруты того же поставщика:

- `/api/liturgical/calendar-texts` — справочные тропари, кондаки, молитвы.
- `/api/liturgical/works` и `/api/liturgical/works/{slug}/versions/{language}` — произведения.
- `/api/calendar/icons` — каталог икон.
- `/api/calendar/icons/{icon}/images/{image}?preview=1` — компактное превью.
- `/api/translations` и маршруты книг/глав — библейский текст.

Описание обоих контрактов Bible Desktop, включая старый snake_case
`/api/calendar/day` для мобильного приложения, находится в его
`docs/KALENDAR_CONNECTION.md`. Форматы не смешиваются.

## WordPress

[Georg-Kloster Calendar Workshop на WordPress.org](https://wordpress.org/plugins/georg-kloster-calendar-workshop/).
Установите плагин через «Плагины → Добавить», найдя его по названию.
Новые версии доступны через стандартные обновления WordPress.
Шорткоды и Gutenberg-блоки сохранены. Календарные данные, тексты и иконы
плагин получает с одного настроенного адреса Bible Desktop. Знаки Типикона,
все 16 оформлений поста, общие декоративные ресурсы и Monomakh с лицензией включены в плагин как статические
ресурсы; их наличие не зависит от внешнего API. Декоративные PNG подготовлены
до 384 px. Галереи икон сохраняют локальный кэш и лимит 200 МБ.

## Порядок обновления

Сначала обновить Bible Desktop и проверить все используемые маршруты, затем
обновить Kalendar штатной сборкой и установить новый ZIP в WordPress.
Сборка Kalendar удаляет прежние неверсионированные обработчики из `dist`.
Старые ZIP с адресом удалённого API больше не публикуются; они сохранены в
локальной резервной копии перед миграцией.

Проверки Kalendar: `npm test`, `npm run typecheck`, `npm run build`,
`npm run test:calendar-api`, `node scripts/test-web-calendar.mjs`,
`node scripts/test-calendar-api-docs.mjs`, `npm run test:print-runtime`,
`node scripts/test-web-calendar-live.mjs`,
`node scripts/test-worship-reader.mjs`,
`npx playwright test e2e/editor-api-migration.spec.ts`.
API-проверка требует сборку и проверяет отсутствие обработчиков, HTTP 404
старых маршрутов и доступность шаблонов сеток редактора.
