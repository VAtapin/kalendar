# WordPress-плагин «Православный календарь»

Исходники: `wordpress/orthocal/`. Установочный архив: `artifacts/orthocal-1.3.41.zip`.
Обычная сборка не меняет публичные скачивания. Копирование в `public/downloads`
включается отдельным флагом `--publish-downloads` после согласования выпуска.
Плагин самостоятельный: PHP 8.0+, WordPress 6.3+, без Node, Vue, локального XML
или расчёта календарных правил на сайте WordPress.

## Установка

1. Обновить календарный сервер кодом текущего проекта и выполнить стандартную
   сборку `npm run build`. Нужны `/upcoming`, `view=summary` для месяца/года,
   новый `/api/v1/calendar-texts/` и `public/data/liturgical-texts.json`.
2. Установить ZIP через «Плагины → Добавить → Загрузить плагин».
3. Сохранить ключ в главном меню «Православный календарь» либо определить
   `ORTHOCAL_API_KEY` в закрытом `wp-config.php`. Проверить оба API.
4. Вставить любой из 19 Gutenberg-блоков или шорткодов из встроенной помощи.

В главном меню плагина три раздела: «Подключение», «Конструктор» и «Помощь». Все свойства конкретного блока — содержание карточки, картинки, иконы, тема, цвет, размер, переходы и перевод Библии — задаются в конструкторе с живым предпросмотром.

Исходники сайта и плагина подготовлены локально; этот документ не означает,
что API уже опубликован или ключ выдан. Требуется отдельно выполнить обычное
развёртывание календаря. ZIP не содержит ключей и не выдаёт доступ автоматически.

## Демонстрационная страница

Можно вставить все блоки на одну страницу:

```text
[orthocal_today]
[orthocal_upcoming limit="5"]
[orthocal_month]
[orthocal_year]
[orthocal_day date="2027-05-02"]
[orthocal_readings date="2027-05-02"]
[orthocal_calendar open="modal"]
[orthocal_fasting]
[orthocal_saints]
[orthocal_feasts limit="5"]
[orthocal_memorial limit="5"]
[orthocal_pascha year="2027"]
[orthocal_fasts year="2027"]
[orthocal_date]
[orthocal_texts]
[orthocal_troparia scope="resurrection" tone="1"]
[orthocal_kontakia scope="weekday" weekday="1"]
[orthocal_prayers]
[orthocal_magnifications]
```

Три темы: book / modern / inherit. Параметры compact и oldstyle принимают 0/1.
Календарь и Библия выбирают языки независимо. Интерфейс первой версии русский.
Параметр `open="inline|modal|page"` задаёт открытие дня, `reading_open="inline|modal"`
— чтения. Для page выберите опубликованную страницу с `[orthocal_day]` в админке.
`sections="fasting,saints,readings,texts,icons"`, `heading="0|1"`, `images="0|1"`
управляют наполнением. Доступны 16 наборов значков поста (`image_pack`).
Профиль поста явно подписывается. Жития и приходские расписания не подключены.

Набор сохраняется в `image_pack` шорткода/блока. Предпросмотр принимает только
ответ для последнего выбора, включая ошибки загрузки. При `no-fast` картинка не
выводится. Знаки икры и полного воздержания общие. Для сравнения собственных
картинок наборов выберите постную дату, например 7 апреля 2027 (рыба).

`image_size="120"` задаёт только высоту картинки поста в пикселях: её ширина
определяется автоматически по пропорциям исходного файла. Старые значения
`small`, `medium`, `large` остаются совместимыми и означают 28, 44 и 72 px.

98 церковнославянских текстов — начальный справочник с фильтрами по типу, гласу,
разделу и дню недели. Песнопения не назначаются датам автоматически. Служебные
редакционные пометки не показываются пользователям. Источники и границы
корпуса описаны в `docs/LITURGICAL-TEXTS.md`. Акафисты запланированы в BibleDesktop,
рабочий API акафистов пока отсутствует.

Иконки включаются секцией `icons`. Плагин читает их из обычного поля `icons`
ответа Calendar API для дня: календарь сам получает записи из стандартного
Bible Desktop API. Для показа плагин кэширует только изображения, чей точный
адрес вернул этот контракт Bible Desktop; отдельных WordPress-маршрутов,
ключей и форматов API для икон нет. Фильтр `orthocal_day_icons` принимает
проверенные локальные файлы `localUrl` из каталога кэша с alt/attribution.

## Архитектура

- `includes/plugin.php`: динамический серверный HTML, API-клиенты, настройки,
  валидация, краткосрочный прикладной кэш и публичные ограниченные REST-маршруты.
- `assets/calendar.js`: независимые экземпляры, AJAX-навигация, ленивый каталог
  переводов и чтения, защита от запоздалых ответов при смене перевода.
- `assets/calendar.css`: изолированные стили, контейнерная адаптация и печать.
- `includes/admin.php`, `assets/admin.js/css`: настройки, конструктор и помощь.
- `includes/media-cache.php`: локальные файлы, условные проверки и очистка.
- `assets/editor.js`, `blocks/*/block.json`: 20 динамических Gutenberg-блоков; каждый также доступен как шорткод.

Calendar API выбирает события и структурированные отрывки; BibleDesktop даёт
каталог книг и главы. Сопоставление по OSIS, проверка языка/перевода, границ и
непрерывности стихов обязательны. При неполных данных текст не показывается как
полное чтение. Нумерация исходного календаря остаётся неподтверждённой.

HTTP-прокси использует только два фиксированных HTTPS-источника, не следует
редиректам и не передаёт календарный ключ BibleDesktop. Настройки доступны
администратору; стандартный WordPress Settings API проверяет nonce и права.
Простые счётчики транзиентов ограничивают обычную нагрузку; для атомарных лимитов
при высокой конкурентности нужен серверный rate limit.

Кэш календаря включается только по заголовку разрешения API, максимум 300 секунд,
без выдачи устаревших данных при ошибке. Библейские ответы сохраняются на
0/1/6/24 часа (по умолчанию 24); запрет no-store без отдельного разрешения API
отключает сохранение. Настройки
инвалидируют поколение кэша. Страницы с блоками/шорткодами в содержимом получают
DONOTCACHEPAGE и no-cache; для блоков в шаблонах/виджетах и CDN исключение из
полностраничного кэша нужно задать в его настройках. Открытая карточка текущего
дня обновляется каждые пять минут, если вкладка видима и чтение не раскрыто.

Картинки поста, знаки Типикона и церковнославянский шрифт сохраняются при первом
использовании в `uploads/orthocal-cache`. Посетитель получает локальные URL.
Проверка через 6/12/24/168 часов выполняется WP-Cron с ETag/Last-Modified;
по умолчанию раз в сутки. При изменении содержимого создаётся новое имя SHA-256,
при сетевой ошибке сохраняется рабочая копия. Старые версии сохраняются до ручной
очистки; общий предел 64 МБ. Админка показывает размер, ошибки и кнопки проверки
и очистки. Медиа-библиотека WordPress не затрагивается. WP-Cron зависит от
посещаемости сайта; для точного расписания нужен серверный запуск wp-cron.php.

## Сборка и проверка

```text
node scripts/build-wordpress-plugin.mjs
node scripts/test-calendar-public-api.mjs
node scripts/test-wordpress-plugin.mjs
npx vitest run tests/liturgical-texts.spec.ts
```

Тест плагина использует настоящий отдельный WordPress и официальный SQLite
drop-in, реальные данные собранного календарного runtime и изолированные
фикстуры HTTP через WordPress pre_http_request. Производственные API и ключи
не используются. Для первого запуска в PowerShell:

```powershell
New-Item -ItemType Directory -Force tmp/orthocal-wp
Invoke-WebRequest https://wordpress.org/latest.zip -OutFile tmp/orthocal-wp/wordpress.zip
Invoke-WebRequest https://downloads.wordpress.org/plugin/sqlite-database-integration.latest-stable.zip -OutFile tmp/orthocal-wp/sqlite.zip
Expand-Archive -LiteralPath tmp/orthocal-wp/wordpress.zip -DestinationPath tmp/orthocal-wp -Force
Expand-Archive -LiteralPath tmp/orthocal-wp/sqlite.zip -DestinationPath tmp/orthocal-wp/wordpress/wp-content/plugins -Force
```

Нужен собранный `dist/api/calendar-runtime.mjs`, PHP с pdo_sqlite/sqlite3
и Edge на Windows (Chromium на других платформах). Тест создаёт локальную БД
и тестового пользователя, проверяет регистрацию, серверный HTML, обычные
permalink без rewrite, REST-навигацию, чтения, отсутствие стихов, отсутствие
ключа в HTML, мобильное переполнение. Снимки сохраняются в artifacts.

Перед публикацией в WordPress.org отдельно нужны карточка плагина, сведения
о владельце/поддержке, окончательные условия внешних сервисов и проверка
на целевых версиях WordPress/PHP. Автопубликация в каталог не выполняется.

## Источник богослужебных текстов

Блоки тропарей, кондаков, молитв и Часослова получают тексты из Bible Desktop API. Kalendar остаётся источником расчёта календарного дня и печати, но не хранит богослужебный корпус.

## Библиотека в 1.3.38

Сначала обновите Bible Desktop и выполните `liturgical:import-library --publish`
и `liturgical:import-public-prayers --publish`. Это подключает сохранённые
переводы и молитвы к действующему API. Затем обновите календарный сайт и ZIP плагина.

Новые шорткоды: `[orthocal_akathists]`, `[orthocal_canons]`.
`text_language` выбирает язык текста отдельно от `lang`: `ru`, `cu`
(традиционная орфография), `cu-civil` (гражданский шрифт), `de`, `pl`, `uk`.
Параметр `work` выбирает произведение по slug Bible Desktop.
Например: `[orthocal_horologion office="sixth-hour" text_language="ru"]`.

В 1.3.39 `cu` и `cu-civil` строго разделены: запрос `cu` не заменяется запросом
`cu-civil`. Общий рендерер полного произведения и справочного песнопения ставит
`data-orthography="traditional"` для `cu` (Monomakh) и `civil` для `cu-civil`
(гражданский шрифт), в том числе при отсутствующем поле orthography в ответе.
Существующие CSS-правила применяются без отдельных исключений по разделам.
Текст не преобразуется. Отсутствие версии показывается как отсутствие текста.

Публичный API на 12.09.2026: у 38 канонов и 3 акафистов нет версий `cu`;
в справочнике песнопений `cu` возвращает 0 записей. В Часослове версии `cu`
доступны у 21 из 35 произведений. Для остальных разделов наличие настоящей
версии `cu` требует отдельной работы с корпусом Bible Desktop, а не замены CSS.

Полные произведения загружаются по одному, справочник — страницами по 100 записей.
Гласы и разделы предлагаются по данным выбранного типа/языка; у величаний без
указанного гласа соответствующий фильтр скрыт. Русские тропари/кондаки доступны
как переведённые сборники. Отсутствующий перевод не заменяется славянским текстом.
Немецкие издания из библиотеки Bible Desktop открываются локально после импорта корпуса; польские внешние источники пока обозначены ссылками.

Проверено: реальный WordPress/SQLite и Edge (22 блока, Gutenberg preview, ключи,
диалоги), отдельный читатель (смена языков и разделов, мобильный размер, закрытие),
API и повторный импорт всего корпуса, 521 тест календаря и production-сборка.
