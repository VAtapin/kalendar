# Развёртывание `kalender.georg-kloster.ru` в Plesk

Производственная версия состоит из статического интерфейса в `dist` и небольшого
PHP-обработчика в `dist/api`. PHP обслуживает подтверждение e-mail, общие ссылки,
блокировку редактирования, настройки, общие макеты и загрузку PDF. Отдельный
Node.js-процесс, systemd-служба и открытый порт приложению не нужны.

Рабочий каталог:

```text
/var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru
```

## Первая сборка и обновления

Команды выполняются системным пользователем сайта, не `root`:

```bash
cd /var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru
git pull --ff-only origin main
nodenv local 22
npm ci --include=dev
npm run build
mkdir -p storage
chmod 700 storage
```

Node.js используется только командой сборки. После завершения `npm run build`
никакой Node.js-процесс не запускается. При необходимости освободить место можно
выполнить `npm prune --omit=dev`; на работу опубликованного сайта это не влияет.

При первой установке создайте конфигурацию:

```bash
cp -n deploy/kalender.env.example .env
chmod 600 .env
nano .env
```

В `.env` заменяются `CALENDAR_OWNER_EMAIL` и `SMTP_PASSWORD`; параметры SMTP
должны соответствовать созданному в Plesk ящику. При обновлении не заменяйте
рабочий `.env` примером. Существующий `MAIL_FROM` поддерживается, новые
`MAIL_FROM_ADDRESS` и `MAIL_FROM_NAME` имеют приоритет. Файл находится выше
`dist` и не выдаётся посетителям сайта. Для локальной отправки через PHP/Plesk
доступен `MAIL_TRANSPORT=sendmail` без SMTP-пароля.

Для доставляемости писем включите в Plesk DKIM-подпись исходящей почты, а у
авторитетного DNS-провайдера домена опубликуйте показанную Plesk запись DKIM,
SPF для отправляющего сервера, а также DMARC. Пока DNS внешний, одной
галочки DKIM в Plesk недостаточно.

## Настройки Plesk

### Администратор, подписки и доступ браузера

Пункт «Файл → Администратор» доступен подтверждённому владельцу из
`CALENDAR_OWNER_EMAIL`. Права проверяются сервером на каждом административном
запросе. Раздел показывает серверные общие календари (с просмотром без захвата
блокировки), пользователей/подписки и последние 2000 событий отправки.
Локальные файлы и IndexedDB других браузеров не передаются в админку.

Подписка добровольная, галочка изначально снята. Одна ссылка подтверждает
адрес и подписку, только если согласие было отмечено при запросе письма.
Хранятся версия/текст согласия, даты запроса и подтверждения, история отписки.
Подтверждённые ранее адреса автоматически не подписываются. Отписка по ссылке
не требует входа и не отзывает доступ к календарям. GET показывает форму,
POST отписывает; просмотр ссылки почтовым сканером не отписывает пользователя.

Рассылка запускается владельцем вручную после проверки текста. Во время
отправки окно должно оставаться открытым; обрабатывается по одному получателю
на запрос. Подписка проверяется перед каждой отправкой. Ошибки и неопределённый
результат не повторяются автоматически во избежание дубликатов. «Принято
почтовым сервером» не означает доставку в ящик. Планировщика и автоматических
напоминаний пока нет. Включение DKIM/SPF/DMARC и политики обработки данных
остаётся обязанностью владельца сервера.

Подтверждённый браузер хранит токен в localStorage без календарного срока
истечения; новые подтверждения больше не вытесняют прежние браузеры. Очистка
данных сайта, другой браузер или отзыв токена требуют нового подтверждения.
При обновлении уже удалённые старой версией токены не восстанавливаются.

Письмо можно подтвердить на другом устройстве. При запросе новый клиент
получает отдельный случайный секрет браузера, который не входит в письмо.
До подтверждения он не даёт доступа. Переход по письму активирует только
исходный браузер; телефон показывает сообщение «Вернитесь к компьютеру».
Компьютер проверяет статус раз в 3 секунды (при ошибке сети — раз в 10 секунд)
и сохраняет вход. Запрос хранится в localStorage и восстанавливается после
закрытия вкладки. Старые письма и старые клиенты сохраняют прежнюю совместимость.

Антиспам использует `email-rate-limits-v2.json`: пауза 60 секунд после успешной
отправки на адрес, не более 100 успешных отправок с IP в час, одна одновременная
отправка на адрес/IP. Ошибки не расходуют квоту. Резерв при аварийном завершении
PHP истекает через 180 секунд. Старый файл счётчиков больше не используется.

Проверки без реальных писем: `php scripts/test-admin.php` и
`node scripts/test-admin-http.mjs`. Тестовые данные создаются только в `tmp/`.

Для субдомена включите обычный режим сайта с PHP 8.1 или новее и стандартный
режим проксирования nginx через Apache. В поле **Document root** укажите:

```text
/var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru/dist
```

Если поле принимает путь относительно каталога подписки:

```text
kalender.georg-kloster.ru/dist
```

Поле **Дополнительные директивы nginx** должно быть пустым. Маршрутизация
`/api/...` уже находится в `dist/.htaccess`; Plesk передаёт эти запросы обычному
PHP-обработчику. Файл `dist/.user.ini` устанавливает лимиты для больших общих
проектов и длительных операций.

Максимально допустимый размер HTTP-запроса в Plesk можно оставить 128 МБ. PDF
передаётся частями по 4 МБ, а общий проект ограничен 100 МБ.

## Проверка

```bash
curl -fsS https://kalender.georg-kloster.ru/api/health
```

Ожидаемый ответ:

```json
{"ok":true,"collaboration":true,"runtime":"php"}
```

## Хранение данных

- До команды «Поделиться для совместной работы…» проект остаётся в браузере и
  локальном файле `.kalendar`.
- Общие проекты находятся в `storage/shared-projects`.
- Аренда редактирования хранится в `storage/leases`, действует 45 секунд и
  продлевается открытым редактором каждые 15 секунд.
- Подтверждённые адреса и настройки находятся в
  `storage/email-identities.json`.
- Общие макеты находятся в `storage/calendar-grid-templates.json`.
- PDF собираются потоково в `storage/pdf-exports` и скачиваются с поддержкой
  продолжения прерванной загрузки.

Каталог `storage` находится вне `dist`, поэтому nginx и Apache не могут отдать
его содержимое напрямую.
