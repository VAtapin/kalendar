# Личные кабинеты и каталог мастерской

Новая установка без переноса прежних календарей. Production: обычный Plesk с PHP, document root — `dist`. Node нужен только для сборки. Отдельный Node-сервис и открытие порта API не нужны.

## Пользователь

- Письмо подтверждает адрес и открывает установку пароля. Та же форма позволяет восстановить забытый пароль. Письмо можно открыть на телефоне: после установки пароля вход на компьютере выполняется по e-mail и паролю.
- Пароль хранится как `password_hash`, сеанс — случайный токен в HttpOnly/SameSite cookie на 30 дней. Сброс/смена пароля и блокировка отзывают сеансы.
- Новый календарь создаётся на сервере; последующие изменения автоматически сохраняются. Ctrl+S явно сохраняет на сервере. Загрузка файла и скачивание копии — отдельные действия.
- При конфликте версий сервер возвращает 409, не перезаписывая чужую более новую версию. Перед открытием другой версии можно скачать несохранённую копию.
- Фотопанель слева принимает JPG/PNG/WebP, поддерживает сворачивание, двойной щелчок и перетаскивание. Фото остаются в библиотеке до размещения. Неизменённые источники не передаются повторно при автосохранении.
- Личные шаблоны и макеты синхронизируются через `/account/library`; локальное вспомогательное хранилище разделено по ID аккаунта.
- История ведётся отдельно для каждого календаря: до 10 точек, не чаще одной в минуту, суммарный объём истории одного календаря до 100 МБ.
- Текущие защитные пределы: 100 календарей на аккаунт, 1 ГБ активных календарей вместе с их историей; до 100 МБ в запросе календаря; до 100 МБ в личной библиотеке. Ошибки лимита показываются пользователю; неуспешное сохранение не считается успешным.
- Пользователь может изменить пароль и согласие на рассылку в настройках кабинета.
- Импорт с компьютера также требует входа и создаёт отдельный серверный календарь. В меню «Файл»: «Сохранить» — сервер; «Скачать копию…» — компьютер, без второго режима редактирования.
- В кабинете есть поиск, скачивание без открытия редактора и собственная корзина с восстановлением. Чужая корзина недоступна даже по известному идентификатору файла.
- При завершении сеанса повторный вход в тот же аккаунт сохраняет открытую работу в памяти редактора; автоматически чужая версия не перезаписывается.
- Кнопка «Фотографии» в инструментах полностью скрывает/открывает фотопанель. Её ширина меняется мышью или стрелками на разделителе; ширина и видимость запоминаются в браузере.
- Перетаскивание на пустую доступную фоторамку заполняет её с сохранением пропорций и обрезкой. Поверх существующей фотографии или на свободное место добавляется отдельный объект. Закрытые и заблокированные слои не заменяются.
- Золотые и SVG-элементы из правой библиотеки можно перетаскивать на страницу. В месте отпускания создаётся отдельный выделенный объект на новом верхнем слое; масштаб учитывается, пропорции сохраняются. Клик для вставки по центру также остаётся. Если во время загрузки элемента переключить календарь/страницу, вставка отменяется.
- Удаление фотографии, вставленной в пустую рамку, сначала очищает рамку. Второе удаление удаляет саму пустую рамку. Отдельные фотографии удаляются сразу; Ctrl+Z отменяет каждый шаг.
- В списке страниц доступны добавление пустой страницы и удаление с подтверждением. Ctrl+Z возвращает удалённую страницу. Минимум одна страница остаётся в календаре.

## Администратор

В библиотеке сеток есть шаблон «Пост цветом»: светлая заливка по существующим категориям поста вместо картинок. Цветная легенда использует те же категории и подписи; режим сохраняется в календаре и выводится в PDF. Его можно применить к выбранному месяцу или ко всем месяцам. В свойствах сетки есть переключатель «Пост цветом».

Вход по отдельному логину/паролю. Первоначальная настройка: `php scripts/setup-admin.php` от пользователя сайта. Пароли пользователей администратор не видит.

- Аккаунты: список, блокировка/разблокировка с отзывом сеансов.
- Календари: просмотр, перемещение в корзину и восстановление оригинальному владельцу. Корзина не очищается автоматически: включите её в резервное копирование и контролируйте диск.
- Каталог: поиск и категории, встроенные и загруженные ресурсы. JPG/PNG/WebP, SVG, TTF/OTF/WOFF/WOFF2, файлы календарей как шаблоны. Максимум одного загружаемого ресурса — 20 МБ.
- Названия и доступность ресурсов редактируются; загруженный файл можно заменить. Выключение не разрушает уже вставленные материалы: они встроены в календарь. Публичные ресурсы не предназначены для приватных фотографий; приватные фотографии загружайте в календарь пользователя.
- Добавлены поиск пользователей и фильтр категорий каталога. Незавершённые HTML-черновики с пустой ссылкой сохраняются, но отправить их до заполнения ссылки нельзя. Существующий черновик загружается при первом открытии рассылки.
- SVG проходит XML-проверку, запрет скриптов/обработчиков/внешних ссылок. Для этого необходим PHP DOM/XML. Растры проверяются через `getimagesizefromstring`, шрифты — по сигнатуре на сервере и загрузке FontFace в браузере.
- Макеты сеток: названия, описания и типографика. Полную геометрию можно подготовить в редакторе и опубликовать для всех.
- HTML-рассылки: блоки текста, заголовков, картинок и кнопок, предпросмотр, серверный черновик, список рассылок и продолжение оставшихся получателей. Подписка проверяется непосредственно перед отправкой; отписавшиеся пропускаются. Статус «принято сервером» не означает доставку. Для отправки окно остаётся открытым; после закрытия можно продолжить через список рассылок. Автоматического расписания отправок нет.

## Данные и эксплуатация

Все изменяемые серверные данные находятся вне document root, в `storage` (или `CALENDAR_DATA_DIR`). `accounts.json`, `calendars/`, `calendar-trash/`, `library-*.json`, `catalog.json`, `catalog-files/`, файлы подписок/рассылок нужно резервировать вместе. Не публикуйте каталог storage и `.env`.

`APP_PUBLIC_URL` должен точно совпадать с HTTPS-адресом сайта: это проверяется для изменяющих запросов. SMTP/Sendmail остаются существующими. Для больших календарей необходимо достаточное ограничение тела запроса в nginx/Apache и память PHP; JSON и резервные версии требуют существенно больше памяти, чем размер одного файла. Проверяйте большие файлы отдельно на используемом PHP-FPM, а не только CLI. Глобальные настройки других сайтов не менялись.

Сохранение освобождает предварительно прочитанную историю перед повторным чтением под блокировкой. Проверка квоты не перечитывает текущий календарь. Это устраняет воспроизведённое исчерпание PHP 768 МБ на годовом календаре с десятью резервными версиями; формат файлов, история и защита от конфликтов версий сохранены.

### Журнал ошибок

Собственный журнал: `CALENDAR_DATA_DIR/logs/errors.jsonl`, в production по документированной конфигурации — `/var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru/storage/logs/errors.jsonl`. Каталог создаётся при обращении к API, файл — при первой ошибке, без изменения `.env`. Записываются ответы API 4xx/5xx, PHP warnings/errors и фатальные сбои (включая нехватку памяти), обработанные ошибки отправки писем и печатного экспорта. В ответах API есть `X-Calendar-Request-Id` для сопоставления с журналом.

Основное Vue-приложение отправляет только технические категории ошибок JavaScript/Vue, необработанных Promise, загрузки ресурсов и HTTP/сетевых запросов; сохранение календаря имеет отдельную категорию `calendar-save`. Отменённые запросы не считаются ошибкой. Сообщения/стеки браузера, URL, параметры, cookies, пароли, e-mail и содержимое календарей не передаются. Клиентские записи не являются доверенным доказательством серверного события.

Успешные запросы не записываются. Журнал содержит время UTC, случайный идентификатор запроса, категорию, код/status; для PHP — имя файла и строку, для исключений — класс. Произвольные сообщения исключений не включаются. Каталог имеет права 0700, файлы 0600; JSONL не выдаётся через HTTP. При 5 МБ сохраняется одна предыдущая копия `errors.jsonl.1`. Клиент ограничен 20 сообщениями в минуту, приёмник — 30 на адрес в минуту с проверкой Origin. Ошибка записи не должна ломать приложение.

Ошибки nginx/Apache до запуска PHP остаются в журналах Plesk. Сетевую ошибку браузера можно записать только если приёмник доступен; отчёты не сохраняются в локальную очередь и не повторяются. Ошибки загрузки до запуска основного приложения и ранние ошибки запуска PHP также требуют стандартных серверных журналов.

```bash
tail -n 100 /var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru/storage/logs/errors.jsonl
```

Проверки без реальной отправки писем:

```sh
npm test
npm run build
php scripts/test-accounts.php
node scripts/test-calendar-save-http.mjs
php scripts/test-catalog.php
php scripts/test-newsletter.php
php scripts/test-admin.php
node scripts/test-admin-http.mjs
```

Браузерные проверки требуют локальный Vite `127.0.0.1:5178` и установленный Edge: `node scripts/test-account-browser.mjs`, `node scripts/test-admin-login-browser.mjs`. Они используют отдельные временные каталоги данных и отключённую отправку писем.
