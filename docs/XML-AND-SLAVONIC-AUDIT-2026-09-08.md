# XML и церковнославянский корпус: фактический результат продолжения аудита

Дата: 8 сентября 2026 года. База сравнения кода: `44c7bc3`.
Пример пользовательского PDF в эту проверку не входит.

## Заключение

**Задание ещё не завершено.** Построен построчный реестр для всех 3811 записей
XML, выполнено автоматизированное сопоставление с внешними источниками и
исправлены подтверждённые дефекты в 17 записях. Но это **не сплошное независимое
редакторское подтверждение** каждой памяти, каждого чина службы, исторического
года и условия переноса. Полного церковнославянского перевода пока нет.

В этой итерации новые церковнославянские переводы в приложение не добавлены.
Массовое включение корпуса Ponomar приостановлено до решения владельца проекта
об использовании сторонних данных на условиях их лицензии. Это не препятствует
сверке фактов, но не позволяет считать перенос корпуса согласованным. Даже
согласованный импорт сам по себе не устранит пробелы и ошибки источника.

## Что изменено в расчётах

1. В обработчик XML добавлен явный код `s_month=-5`: первый указанный день
   недели **строго после** даты `f_month/f_date` старого стиля. `s_date` задаёт
   день недели: 0 — воскресенье, 6 — суббота. Для Пахомия: `-5, 6, 1, 6`.
   При совпадении Богоявления с субботой память приходится на следующую субботу,
   а не исчезает и не остаётся в сам праздник. Семантика прежних кодов не менялась.
2. Убран выдуманный обязательный пост с маслом в понедельник после Недели
   о блудном сыне. В этом понедельнике теперь `no-fast` в обоих профилях.
   Пост среды и пятницы не отменён. Основания:
   [правила подготовительных седмиц](https://azbyka.ru/o-postax-i-trapezax),
   [контрольный день 9 февраля 2026](https://days.pravoslavie.ru/Days/20260127.html).

## Масштаб фактически выполненной внешней сверки

Взяты **366 календарных страниц** `days.pravoslavie.ru` с проверкой даты ответа:
все числа каждого месяца старого стиля за 2026 год; для 29 февраля — 2024 год.
Старостильный 2026 год захватывает гражданские 2026 и 2027 годы. Это не проверка
всех гражданских дней 2027 года или всех возможных будущих переносов.
Сохранены URL, дата получения и SHA-256 каждой страницы. Рабочие выдержки
находятся только в игнорируемом `tmp/`; длинные жития и молитвы не импортируются.

Дополнительно сопоставлены русские именные записи и календарные индексы
[Ponomar, закреплённая ревизия](https://github.com/typiconman/ponomar/tree/0af645f438856f45c22026912d2e4a9ce495e531).
Условия `Cmd` не исполняются, значение `SERVICE Type` не приравнивается без
основания к нашему `type`. Сам Ponomar не объявляется безошибочным эталоном.

двумя независимыми историческими свидетельствами.

## Постные правила: отдельная контрольная матрица

[Матрица 366 дат](audit-data/fasting-independent-2026-09-08.json) сравнивает
внешнюю подпись с обоими профилями программы. После устранения ложного
понедельничного поста: 290 совпадений категорий со строгим профилем,
75 расхождений для разбора, 1 страница без извлечённой постной подписи.

**75 расхождений не означают 75 доказанных ошибок программы.** Здесь смешиваются
различия уставных мер, степень детализации категорий, праздничные послабления
и потенциальные ошибки. Например, полное воздержание отдельно написано на сайте,
а в приложении относится к общей категории `strict-fast`; разрешение икры
описано в причине правила, но не выделено отдельной печатной категорией.
Порядок первой седмицы, праздничные послабления, меры Петрова/Рождественского
постов и отдельные строгие/приходские различия ещё нужно разрешить по точным
уставным ссылкам. Массового переписывания правил под один веб-календарь не было.

## Церковнославянский: что установлено

[Полная инвентаризация текущих строк и технических проблем](audit-data/church-slavonic-coverage-2026-09-08.json)
включает:

- Полные названия всех XML-записей, их краткие и очень краткие варианты.
- Описания XML, даже если нынешняя сетка их непосредственно не печатает.
- Генерируемые названия богослужебного цикла и их варианты для 1900–2199 годов.
- Месяцы, полные/краткие дни недели, постные подписи, обозначение старого стиля,
  подпись монастырского события, русский заголовок обложки и «Новый текст».

Это 5621 различная строка основного инвентаря плюс служебные словари.
Для 5508 строк локализатор возвращает русский оригинал; 34 проходят точный
словарь, 79 — структурную локализацию. В подмножестве **2528 уникальных полных
названий памятей**: 24 точных, 29 структурных, **2475 непереведённых**.
Срабатывание словаря не равно филологической проверке правильности его текста.

Проверка реального `cmap` встроенного Monomakh для текущего набора строк
не нашла отсутствующих глифов. Это доказывает наличие символов в шрифте,
**не** правильность ударений, титл, придыханий, склонения и состава имён.

Во внешнем корпусе просмотрены именные поля 3046 записей: 3035 имеют
церковнославянское название. Найдено **84 именных поля** с техническими
замечаниями: управляющие символы, отсутствие надстрочных знаков, совпадение
с русской строкой, посторонние латинские буквы или проблемы глифов. Это не
84 окончательных филологических ошибки; в том числе проверяются короткие формы.
Например, в имени Преображения, CId 4386, имеется недопустимый `U+0099`.
Внешние поля `Short` также нередко обрывают полное именование. Их нельзя
без проверки просто включить вместо нашего текста.

Для пользовательского текста, названия издателя, вручную внесённых событий,
текста внутри загруженных картинок и фирменного баннера требуется отдельная
языковая версия от автора. Произвольный пользовательский текст не заменяется
автоматически и не объявляется заранее переведённым.

## Незакрытые вопросы

- Редакторская сверка оставшихся несовпадений XML, включая современные группы
  новомучеников с фамилиями, все чины служб, исторические годы и описания.
- Проверка всех условий и диапазонов; одной годовой сетки для этого недостаточно.
- В частности, отдельного разбора требуют записи 885 (Кипрская в Стромыни),
  1141 (Шио Мгвимский), 1662 (Липсийские мученики), 1774 (Иерофей/Стефан
  Венгерские). Отличие даты в другом корпусе пока **не** принято за доказанную
  ошибку: возможны переходящие или местные памяти, разные стили и несколько дат.
- Полная церковнославянская редакция 2475 пока непереведённых полных названий,
  их печатных вариантов и остальных встроенных текстов с проверкой диакритики.
- Решение по условиям массового использования данных Ponomar; лицензия
  приложения не изменялась. Если этот источник не согласован, нужен собственный
  перевод/другой разрешённый корпус, а не механическое переименование букв.

## Проверки и воспроизведение

Прошли **372 теста в 50 файлах**, `npm run build` и отдельная проверка TypeScript
новых скриптов. Сборка сохраняет предупреждение о крупном PDF-чанке; это не
ошибка сборки и не связано с импортом нового словаря — его не было.
Браузерные E2E в этой итерации не запускались.

Добавлены 13 регрессионных тестов: журнал названий/дат, сохранение 3811 записей,
оборванные названия, полнота строк сопоставления, технические дефекты диакритики,
Пахомий в 2019/2024/2026/2027 годах, четыре исправленные фиксированные даты,
отсутствие ложного понедельничного поста в обоих профилях.

Команды (из корня проекта, при наличии рабочего снимка Ponomar указанной ревизии
в `tmp/ponomar-source/Ponomar/languages`):

```powershell
node scripts/fetch-independent-calendar-days.mjs
node --import tsx scripts/build-xml-source-ledger.ts
node --import tsx scripts/audit-independent-xml.ts
node --import tsx scripts/audit-independent-fasting.ts
node --import tsx scripts/audit-church-slavonic-corpus.ts
git show 44c7bc3:public/data/MemoryDays.xml | node --import tsx scripts/verify-xml-corrections.ts
npm test
npm run build
```

Скрипты сопоставления не изменяют XML и ничего автоматически не «одобряют».
Рабочие материалы внешних источников остаются в `tmp/`; отчёты не входят
в клиентскую сборку сайта. Обновление сайта на сервере не выполнялось.
