# Адреса приложения

- `/` — стартовая страница.
- `/account`, `/login` — личный кабинет и вход.
- `/calendar/ID` — календарь владельца; без сессии сначала открывается вход.
- `/admin` — администратор, вход по паролю.
- `/admin/pages`, `/admin/templates`, `/admin/newsletter`, `/admin/catalog`,
  `/admin/accounts`, `/admin/subscribers`, `/admin/mail-log`, `/admin/trash`,
  `/admin/ai` — разделы администратора.
- `/impressum`, `/datenschutz`, `/agb`, `/<slug>` — опубликованные страницы.

Переходы используют History API: ссылки можно копировать, открывать в другой
вкладке и обновлять; работают кнопки браузера назад/вперёд. Редактор остаётся
смонтированным при чтении публичных страниц, сохраняя текущую работу в памяти.
Сервер по-прежнему проверяет владельца календаря и права администратора.
Служебные адреса нельзя занимать страницами CMS.

Миграций данных и совместимости со старыми адресами нет.
Письменные токены регистрации/сброса пароля остаются отдельным механизмом входа.

Apache/Plesk: существующий `public/.htaccess` (копируется в `dist`) направляет
нефайловые адреса в `index.html`, `/api/*` — в PHP. Если перед Apache установлен
nginx, запросы этих адресов должны доходить до Apache, а не завершаться nginx 404.
Для самостоятельного nginx требуется аналогичный fallback `try_files $uri $uri/ /index.html`
в обработчике frontend, отдельно от API. Конфигурация production в этой задаче не менялась.

Проверка: запустить Vite на порту 5178 и `node scripts/test-navigation-browser.mjs`.
Тест использует отдельное локальное PHP-хранилище без реальных писем.
