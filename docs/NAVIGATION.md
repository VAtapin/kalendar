# Адреса приложения

Русский: `https://kalender.georg-kloster.ru/` без языкового префикса.
Немецкий: `https://kalender.georg-kloster.de/` без языкового префикса.
Английский/украинский: `.ru/en/` и `.ru/uk/`. Правило одинаково для всех разделов.
Язык браузера и сохранённые предпочтения не переопределяют домен/URL.
Язык печатного календаря остаётся отдельной настройкой.

Переключение RU/DE переносит вход пользователя и администратора: source/create →
target/bind → source/authorize → target/redeem. Одноразовый код действует 120 секунд,
привязан к HttpOnly Secure SameSite=Strict cookie на ОБОИХ доменах. Постоянные токены
не передаются в URL/JSON браузеру. Ссылки шагов используют fragment, не query.
Состояние хранится приватно в `domain-sessions.json` и удаляется при использовании;
просроченные записи очищаются при следующей операции. Сессия общая серверная:
выход или отзыв сессии прекращает её действие на обоих доменах.
Перед переключением редактор дожидается сохранения открытого серверного календаря.

Для общего входа оба HTTPS-домена должны обслуживаться одной установкой и одним
`CALENDAR_DATA_DIR` (Plesk alias). Origin-проверка разрешает только два точных адреса,
когда APP_PUBLIC_URL равен одному из них; CORS и wildcard-доступ не включаются.
Cookies остаются host-only. Пароль повторно не требуется при переключении языка.
Тесты: `php scripts/test-domain-session.php`, `node scripts/test-domain-browser.mjs`.
Последний тест использует HTTPS-адреса алиасов, перехваченные на локальные серверы,
и не изменяет боевые аккаунты.

- `/` — стартовая страница.
- `/account`, `/login` — личный кабинет и вход.
- `/calendar/ID` — календарь владельца; без сессии сначала открывается вход.
- `/admin` — администратор, вход по паролю.
- `/admin/pages`, `/admin/templates`, `/admin/newsletter`, `/admin/catalog`,
  `/admin/accounts`, `/admin/subscribers`, `/admin/mail-log`, `/admin/trash`,
  `/admin/ai` — разделы администратора.
- `/impressum`, `/datenschutz`, `/agb`, `/<slug>` — опубликованные страницы.

Переходы используют History API: ссылки можно копировать, открывать в другой
вкладке и обновлять; работают кнопки браузера назад/вперёд. Редактор остаётся
смонтированным при чтении публичных страниц, сохраняя текущую работу в памяти.
Сервер по-прежнему проверяет владельца календаря и права администратора.
Служебные адреса нельзя занимать страницами CMS.

Миграций данных и совместимости со старыми адресами нет.
Письменные токены регистрации/сброса пароля остаются отдельным механизмом входа.

Apache/Plesk: существующий `public/.htaccess` (копируется в `dist`) направляет
нефайловые адреса в `index.html`, `/api/*` — в PHP. Если перед Apache установлен
nginx, запросы этих адресов должны доходить до Apache, а не завершаться nginx 404.
Для самостоятельного nginx требуется аналогичный fallback `try_files $uri $uri/ /index.html`
в обработчике frontend, отдельно от API. Конфигурация production в этой задаче не менялась.

Проверка: запустить Vite на порту 5178 и `node scripts/test-navigation-browser.mjs`.
Тест использует отдельное локальное PHP-хранилище без реальных писем.
