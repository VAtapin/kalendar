# API и WordPress — выпуск 1.2.0

Сделано:

- Кнопка «API календаря» на главной; отдельная лениво загружаемая страница `/calendar-api` с подключением, параметрами, ошибками, кэшем, тарифами, тестовой страницей и скачиванием.
- Публичные тарифы и контакт загружаются из админки. Выдача, ротация, отключение ключей, срок действия и квоты остаются серверными. Цена — ручное соглашение, не платёжная система.
- API `upcoming`, `view=summary` для месяца/года и явное разрешение кэша приложения на 300 секунд.
- WordPress-плагин: 19 блоков и шорткодов, три темы, компактное представление, пять языков календаря, старый стиль, переключение дат, знаки Типикона, библейские ссылки и отдельная загрузка текста через BibleDesktop. Версия 1.2.0 переносит все параметры отображения в живой конструктор шорткодов и корректно читает обёртку ответов BibleDesktop `{data: ...}`. XML и календарного движка в ZIP нет.
- Архив `/downloads/orthocal-1.2.0.zip` и подробное руководство `/downloads/calendar-api-guide.md` включаются в обычную сборку сайта.

Проверено локально: настоящий PHP/Node HTTP API с изолированным хранилищем; тарифы, ключи и лимиты; отдельный WordPress с SQLite и браузером Edge; все 19 блоков, настройки, навигация, отсутствие ключа в HTML, экранирование текста, ошибки чтений, мобильное переполнение. Отдельный PHP-процесс подтвердил повторную выдачу даты из постоянного WordPress-кэша без вызова API. HTTP-источники WordPress в тесте подменены контролируемыми фикстурами, а данные календаря взяты из собранного runtime.

Страница документации проверена браузером: переход с главной и перезагрузка, тарифы, контакт, настоящий ZIP и Markdown, мобильная ширина, отсутствие загрузки редактора. Production-сервер и WordPress пользователя тесты не меняли. Публикация в каталоге WordPress.org не выполнялась и не требуется для установки ZIP.

Ограничения: интерфейс первой версии плагина русский; нет изображений икон святых, житий и местного расписания. Кэш приложения — до пяти минут, не бессрочный: иначе изменения базы и отзыв ключа не могли бы применяться своевременно. Для CDN/полностраничного кэша нужны исключения страниц календаря. Тексты BibleDesktop зависят от доступности его API и выбранного перевода.

Обновление сайта: обычные `git pull --ff-only origin main`, `npm ci --include=dev`, `npm run build`. ZIP уже лежит в репозитории; на сервере дополнительная сборка WordPress не нужна. Для изменения исходников плагина сначала выполните локально `node scripts/build-wordpress-plugin.mjs --publish-downloads` и включите обновлённый публичный ZIP в коммит.
