# Импорт икон в календарь

Владелец данных — Kalendar. BibleDesktop использует проверенные изображения
через API календаря. Рабочий архив хранится вне публичного сайта:
`data/icon-library/catalog.json`, `originals/`, `pages/`.

Запуск: `node scripts/import-azbyka-icons.mjs`. Только один каталог: `node scripts/import-azbyka-icons.mjs --kind=savior`.
Статус: `node scripts/icon-import-status.mjs`.
Кандидаты привязок: `node scripts/suggest-icon-mappings.mjs`.
Проверка разбора: `node --test scripts/test-icon-card-parser.mjs`.

Загрузчик продолжает существующий каталог, сохраняет каждую загрузку, оригиналы
по SHA-256 и HTML карточек для повторного разбора без сети. Единственный процесс
защищён PID-блокировкой. Соблюдается опубликованный источником Crawl-delay: 30.
404/410 отмечаются как отсутствующий источник; другие HTTP/сетевые ошибки
останавливают процесс с сохранением прогресса. После исправления причины запуск
той же команды продолжит работу. `--max=N` ограничивает число обработанных карточек; `--kind=mother-of-god|savior|saint` ограничивает один каталог.

Даты источника сохраняются как примеры гражданских дат, не как вычисленные
ежегодные правила. Привязки по именам — предложения для проверки, не автоматическое
назначение святому. Скачивание не меняет статус проверки прав или соответствий.
Рабочий архив не включать в публичный API и git-выпуск как проверенную библиотеку.
Отдельный проверенный публичный каталог находится в `src/calendar/api/icon-catalog.ts`.

На 9 сентября 2026 начальный индекс содержит 3498 карточек. Полный сбор занимает
больше суток: даже один запрос на каждую карточку при интервале 30 секунд — около
29 часов, без учёта запросов изображений. Параллельные исполнители разбирают HTML
и готовят привязки локально; они не создают дополнительные сетевые потоки к источнику.
