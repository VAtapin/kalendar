# Календарные данные редактора

Редактор получает публичные календарные данные только из API BibleDesktop,
с адреса PUBLIC_API_URL. Главный редактор, VisualGridEditor, предпросмотр
администратора, экранная сетка и оба пути PDF используют один адаптер снимка.
Фиксированные/переходящие праздники, чтения, переводы и пост в браузере больше
не рассчитываются. Проверка production-бандла запрещает соответствующие модули.
Справочное ядро в src/calendar/engine и fasting-api используется только тестами,
аудитами и сравнением источников; серверного календарного API Kalendar нет.

## Контракт и сохранение

GET `/api/v1/calendar/editor-year?year=2027&lang=ru&profile=typikon-strict`.
Годы 1900–2200, языки ru/cu/de/uk/pl. Один ответ содержит оба профиля поста;
selectedProfile фиксирует лишь первоначальный выбор. Переключение профиля
не запрашивает новый год и работает при недоступном API.

schemaVersion=1; contentHash/runtimeVersion/datasetVersion — SHA-256.
Хэш проверяется WebCrypto до использования. Канонический JSON рекурсивно
сортирует ключи, сохраняет массивы; из payload исключается только contentHash.
Схема, все дни года/даты/события и оба набора поста проверяются отдельно.
Переводы хранятся в event.apiLocalization; исходное title остаётся для фильтров.

В CalendarProject добавлено необязательное calendarSnapshot:
`{fetchedAt, snapshot}`. Оно сохраняется в .kalendar, автовосстановлении,
серверных/общих проектах, резервных копиях и пользовательских шаблонах.
calendarData остаётся прежним transient-полем и по-прежнему обнуляется.
Формат проекта/архива совместим со schemaVersion=1; старые файлы без снимка
получают данные при первом открытии и сохраняют их при следующем сохранении.

Undo/redo хранит версии снимков в пуле, не копируя мегабайты в каждую строку
истории. Копия проекта на другой год очищает снимок прежнего года. Локальный
публичный IndexedDB-кэш ограничен 12 снимками и отделён от приватной БД проектов:
обновления её схемы и блокировки старых вкладок не требуется.

Снимок сохранённого проекта имеет приоритет над сетью и кэшем, независимо
от возраста. Он не заменяется при открытии, печати или фоновой загрузке.
«Обновить календарные данные» требует подтверждения и создаёт резервную копию;
неудачный запрос сохраняет прежний снимок. Повреждённый хэш не подменяется
молча свежими данными; такой проект не печатается до восстановления/обновления.
HTTP 429 учитывает Retry-After, запоздалый ответ не меняет другой год/язык/проект.

## Что остаётся локальным

Частные monasteryEvents, редакторские пометки, изображения, шрифты, геометрия
в миллиметрах, размещение/сокращение текста и PDF-настройки остаются в проекте.
Частные данные не отправляются в календарный API. Дополнительные события
накладываются на копию публичного года, не меняя исходный снимок.
Печатная политика «поминовение вместо картинки поста» сохраняется.

При недоступном BibleDesktop сохранённый проект/кэш дают календарные данные
без API-запроса. Новый год/язык без сохранённого снимка требует соединения.
Это не офлайн-установка всего сайта: загрузка интерфейса/несохранённых шрифтов
и медиа может требовать Kalendar, а серверный PDF/X и его загрузка — сервер,
как и прежде. Чтения/события для уже сохранённой печати не зависят от повторного
запроса календарного API. Иконы, вставленные пользователем, остаются его assets;
годовой endpoint не скачивает галереи всех 365 дней.

## Проверки и публикация

- npm test; npm run typecheck; npm run test:editor-api.
- npx tsx scripts/audit-browser-bundle.ts editor-api — локального ядра нет.
- npx playwright test e2e/editor-api-migration.spec.ts — сохранение и повторное
  открытие 13-страничного проекта при заблокированном API, без MemoryDays.xml.
- npm run build; npm run test:calendar-api; npm run test:print-runtime.
- PHP 8.4: scripts/test-editor-snapshot-storage.php — настоящие снимки пяти
  языков сохраняются и повторно открываются с серверной историей восстановления.

Сжатые fixtures в tests/fixtures/editor-calendar-2027-{ru,de,cu,uk,pl}.json.gz
получены настоящим PublicCalendarService BibleDesktop, проверены по hash
и всем дням/событиям/печатным названиям/обоим профилям. Это публичные тестовые
данные, не ответы, которыми production заменяет внешнюю интеграцию.
Их обновляет scripts/test-editor-api-integration.ts --capture из новых
проверенных tmp/editor-snapshot-2027-*.json, полученных у BibleDesktop.

CLI export:sample тоже использует API; второй аргумент — календарный язык.
EDITOR_SNAPSHOT_FIXTURE позволяет печатать заранее проверенный JSON/JSON.gz
без сети. Полный RGB PDF проверяется отдельно от серверного PDF/X.

Сначала обновить BibleDesktop до c91448b4 или новее (снимки и перенос памятей
29 февраля на 28 февраля в невисокосный юлианский год). Команда и схема в его
docs/KALENDAR_EDITOR_SNAPSHOT.md. Затем в Kalendar:

```bash
cd /var/www/vhosts/georg-kloster.ru/kalender.georg-kloster.ru && \
git pull --ff-only origin main && \
nodenv local 22 && \
npm ci --include=dev && \
npm run check:editor-api && \
npm run build
```

Проверка поставщика до сборки не позволяет опубликовать зависимый редактор,
если новый API ещё не доступен. Она использует фактический PUBLIC_API_URL
из окружения проекта. Внутренние функции входа/хранения/заказов/PDF сохранены.
